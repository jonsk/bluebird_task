# Note 模块前端开发方案

> 本文档为 note 模块**前端**实现契约：页面、路由、组件契约、交互、单测与验收。
>   
> 数据模型、API schema 与后端判定规则见《Note 模块后端开发方案》；总览见《Note 模块集成方案》。

## 1. 背景与目标

note 模块以 Memos v0.31.0 的能力为蓝本，后端以 Java 重写后并入 BlueBird Task（`modules/note`），前端在现有 Vue 3 工程内新增页面。前端目标：

- **与任务模块同构**：统一视图 + 共享列表 + Pinia——`NoteListView`（布局壳）→ `NoteList`（容器）→ `NoteCard`（卡片）→ `useNoteList`（查询/分页/竞态）→ `stores/note`（跨页状态）。7 个 scope 页只写"scope 配置 + 标题 + 权限分支"，不复制列表逻辑。
- **权限驱动渲染**：所有按钮由后端下发的 `canEdit` / `canManage` / `canRemoveRef` / `canRemoveFromTask` 决定，前端**不**用 `ownerId===me` 或 `!archived` 自行推导（矩阵见 §7.4）。
- **纯文本编辑器**：不做 markdown、不做富文本；"工作日志"是个人工作台账，不是私人日记或想法，文案统一称"工作日志"。
- **组件复用优先**：`BbFilterRail` / `BbMiniCalendar` / `BbTagPicker` / `BbUserPicker` / `BbAttachmentList` 按本方案改造后复用，不新建重复组件。

技术栈：Vue 3 + TypeScript + Element Plus + Tailwind；Pinia；MSW（mock）；Vitest + Vue Test Utils（单测）；e2e 沿用工程现有框架。

**契约来源**：接口路径、请求/响应 schema、字段级权限与错误码见《Note 模块后端开发方案》§5、§7、§8；页面、路由、组件契约与交互见本文档 §4–§7；前后端取舍结论见两份文档共用的"决策结论"表。

## 3. 接口契约摘要

> 完整 schema（字段类型、枚举、校验、状态机）以《Note 模块后端开发方案》§5 为准；本节只列前端编码直接依赖的部分。

### 3.1 通用约定

- 基础路径 `/api/v1`，**全部接口需登录**（`Authorization: Bearer <token>`）。
- 响应统一 `ApiResult`：`{ code, message, data, traceId }`，`code===0` 为成功。
- **两类错误分开处理**：
  - HTTP 协议级错误（400/401/403/404/405）→ 拦截器抛 `HttpError(status, data?, message, traceId?)`，页面读 `err.status`（如详情页 `err.status===404` 渲染 notFound，下属页 `err.status===403` 渲染空态）。
  - 业务错误（HTTP 200 + `code!==0`）→ 抛 `BizError(code, message, traceId)`，页面按 `code` 分支（映射见 §3.4）。
  - **401 分流**：先尝试解析响应体的 `code`（JSON 直接读，blob 先 `await data.text()` 再 `JSON.parse`）——可解析且 `code∈{10002,20005}` → 续签并重放一次（`_retried` 防循环）；**解析不出 `code`（无 body）或为其他 code → 直接跳登录，不重放**。
- 列表统一 `PageResult`：`{ list, total, page, size }`；`page` 从 1 开始，`size` 上限 100（超出后端截断）。
- **附件下载/预览一律走 `responseType:'blob'`**（`<a href>`/`window.open` 直连不带 Bearer，会被 401）。blob 响应是否按 `ApiResult` 解析由拦截器统一判定，业务层不二次解析（细则见 §7.7）。**blob 端点的协议级错误（401/403）响应体是 `ApiResult` JSON**（后端文档 §5.4）：错误拦截器遇 `responseType==='blob'` 且 `data instanceof Blob` 时先 `await data.text()` 再 `JSON.parse`，解析失败则把原始文本作为 message 透传。
- `scope` 枚举：`mine | shared | explore | internal | subordinate | visible | all`；`all` 仅 ADMIN；**日历 UI 不暴露 `visible`**。

### 3.3 前端依赖的 VO 字段

| 类型                 | 前端使用要点                                                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| `NoteBrief`        | 列表卡片数据源；含 `canEdit` / `canManage` / `version`；**不含 `ownerTags`**                                            |
| `NoteVO`           | 基础视图；含 `tags`（本 note 已选）、`grantRole`；**不含 `ownerTags`**                                                     |
| `NoteDetailVO`     | `NoteVO` + `relations` / `backlinks` / `attachments` + **唯一的 `ownerTags`**（**`POST /notes`/`PUT`/`GET` 三个入口都必须返回完整结构，`attachments`/`relations`/`backlinks` 至少为空数组、`ownerTags` 至少为 `[]` 或 `undefined`**——临时卡片附件区依赖创建响应的 `attachments`，缺字段会退化成"无附件入口"）；行内编辑必须先取它（不能用 `NoteBrief` 摘要当全文） |

| `NoteRelationVO`   | `id` / `targetType` / `targetId` / `targetSummary` / `createdAt` / `createdBy` / `createdByName`            |
| `NoteAttachmentVO` | `id`（=关联 id）/ `attachmentId` / `downloadUrl` / `canRemoveRef` / `canDelete` / `createdBy`                   |
| `NoteUserGrantVO`  | 双人（grantor/grantee）+ `role` / `status` / `mode` / `direction` / `createdBy` / 审批与撤销字段 / `can*`              |
| `FileVO`           | `downloadUrl` / `createdBy` / `canDelete` / **`canRemoveFromTask`**（task 删除按钮唯一依据；**仅在 task 附件上下文返回，通用 `/files` 响应不带该字段**；前端一律 `=== true` 判断，`null`/`undefined`/非布尔均按 false 处理）                          |
| 日历                 | `Array<{ date: 'YYYY-MM-DD', count: number }>`                                                              |
| `PageResult<T>`    | `{ list, total, page, size }`（`/tasks/search`、`/users` 同构）                                                  |

### 3.4 错误码与页面分支

`errorCode.ts` 与后端 §8 一一对应（文案统一"工作日志"）：

| 业务码           | 常量                                                         | 前端分支                                                              |
| ------------- | ---------------------------------------------------------- | ----------------------------------------------------------------- |
| 50001         | `NOTE_NOT_FOUND`                                           | 详情页 notFound 空态（HTTP 层通常已是 404）                                   |
| 50002         | `NOTE_CONTENT_TOO_LONG`                                    | 编辑器内联提示，不关闭编辑态                                                    |
| 50006         | `NOTE_RELATION_TARGET_NOT_FOUND`                           | 引用选择器提示"目标已失效"并刷新                                                 |
| 50007 / 50008 | `NOTE_GRANT_DUPLICATE` / `NOTE_GRANT_SELF`                 | 授权表单内联提示                                                          |
| 50013         | `NOTE_FIELD_FORBIDDEN`                                     | **仍须 catch**（EDITOR 前端已禁用，但改包/并发/归档态仍可达）：编辑器字段级内联提示"该字段无权修改"，不关闭编辑态；`canEdit/canManage` 前置禁用只是第一道防线 |
| 50016         | `NOTE_SCOPE_DISABLED`                                      | **前端不建任何分支**（`errorCode.ts` 只定义常量、不做映射）：`scope=subordinate` 开关关闭实际返回 HTTP 403，页面按 `err.status===403` 渲染空态 |
| 50020 / 50021 | `TASK_ATTACHMENT_NOT_LINKED` / `TASK_ATTACHMENT_FORBIDDEN` | task 附件场景提示；note 侧不触发                                             |
| 50003         | `NOTE_TAG_INVALID`                                         | 编辑器内联提示"标签已失效，请重新选择"，刷新 `facets.retry()` 后重试                     |
| 50012         | `NOTE_LOG_DATE_INVALID`                                    | 日期控件内联提示"日志日期不能晚于今天 + 7 天"，不关闭编辑态                               |
| 50014         | `NOTE_GRANT_FLOW_FORBIDDEN`                                | 授权页 toast"当前状态不允许该操作"，随后 `reload()` 拉最新状态                           |
| 10006 / 50017 | `VERSION_CONFLICT` / `NOTE_DEPT_REQUIRED`                  | 冲突→§7.9 三动作；无部门→保存时提示"当前账号无部门，无法设为本部门可见"                     |
| 10002 / 20005 | token 过期/失效                                                | 拦截器续签并重放，失败跳登录                                                    |
| 其它 5xxxx     | 未在上表列出的码                                             | **统一兜底**：`toast(err.message)`，不改变页面状态（不落空白/不丢草稿）                                |

> **常量范围**：`errorCode.ts` 定义全部 5xxxx 常量（含仅作语义标识、前端无分支的 50011/50015/50018/50019/50021），但**只给上表列出的码建渲染分支**；未列出的码走统一兜底。**协议级 vs 业务码**：`50016`（subordinate 开关）/`50011`（SUPERIOR 只能选下属）/`50015`（mode 非法）/`50018`/`50019`/`50021` 在后端**均为 HTTP 4xx，不出现在 200 响应里**，前端只按 `err.status` 处理，联调时逐条核对（见 §9 行 12a/18/29a）。

乐观锁冲突（`version` 不一致）按 `VERSION_CONFLICT`（10006）处理：提示并重新拉取最新详情，**保留用户草稿**不丢弃。

- **日历（通用化改造）**：把 `BbMiniCalendar` **改造成通用组件**，任务页零改动、note 版传自己的 `loader`：
  ```ts
  props: { loader?: (year: number, month: number, scope?: string) => Promise<Array<{date:string;count:number}>>;
                                                                    // loader 可选：缺省用组件内任务默认 loader（忽略 scope）；note 传自己的日历取数
           scope?: NoteScope;   // 仅 note 传入；组件内 watch(() => props.scope, () => load()) 重新取数（含默认 loader 时按 scope 变化重建请求）
           height?: number;     // 默认 280；用 :style="{ '--bb-calendar-height': height+'px' }" 注入 CSS 变量，

  emits: { (e:'select-date', date: string|null): void }   // 点日带出（date 形如 YYYY-MM-DD）
  ```
  **loader 缺省语义**：`loader` 为**可选 props**；**不传时使用组件内置任务日历默认 loader**（任务页零改动、忽略 `scope`）；传入时 task/note 自定义取数。**`scope` 变化总是触发 `load()` 重新取数**（无论用默认 loader 还是自定义 loader）。**`loader` 类型统一为 `(year:number, month:number, scope?:string) => Promise<Array<{date:string;count:number}>>`**：内置任务 loader 忽略 `scope`，note loader 必须消费 `scope`。**但 `scope` 必须与自定义 `loader` 成对传入**：只传 `scope` 不传 `loader` 时，dev 环境 `console.warn` 并**按"忽略 scope"的默认 loader 取数**（本次 `load()` 照常执行，只是 loader 忽略 scope，不会"按 scope 重建 note 请求"），避免"按 scope 重取却无 note loader"的空跑路径；类型上同样用"二者同有同无"的可辨识联合表达。

  **竞态与回归**：`load()` 用请求序号/`AbortController` 取消上一请求，**旧月份响应迟到不得覆盖新月份**；`loader` 抛错 → 显示卡片级错误态 + 重试按钮；`selected` 从外部变化仅设日期、不强制切月（与现有 `:37-42` 一致）。

  `useMonthCalendar(loader, opts?: { initialScope?: NoteCalendarScope; initialYear?: number; initialMonth?: number; initialDate?: string | null; syncRoute?: boolean })`（`initialScope` 类型为 `NoteCalendarScope`，与 `MonthCalendarState.scope` 类型一致） 契约：
  ```ts
  interface MonthCalendarState {
    year: number; month: number; loading: boolean; error: string | null
    days: Array<{ date: string; count: number }>
    selected: string | null
    scope: NoteCalendarScope; setScope(s: NoteCalendarScope): void     // scope 类型为 NoteCalendarScope = Exclude<NoteScope,'visible'>（日历不暴露 visible scope，6 个 scope）；setScope 对非法值 **dev 警告 + 忽略（保持原 scope，不抛错、不回退默认）**
  ```

`useMonthCalendar` 增加 URL 同步职责——`prevMonth/nextMonth/select/setScope` 都写 URL（`/notes/calendar?scope=&year=&month=&date=`）；`initialYear/initialMonth/initialDate` 从 `route.query` 读取（`NoteCalendarView` 调用前归一化后传入）；`syncRoute=true`（默认）时 composable 内部 `watch` route.query 变化并重新加载。**防双请求**：写 URL 与取数统一走内部单一 `apply()` 入口（`prevMonth/nextMonth/select/setScope` 先改 state、再 `apply()` 一次），`applying` 标记抑制 `watch` 回环，避免"改 URL → watch → 再 reload"的重复请求。`initialYear/initialMonth/initialDate` 解决刷新/后退恢复。竞态取消逻辑放进 `useMonthCalendar`（`loader` 接受 `signal: AbortSignal` 参数或内部用请求序号），`BbMiniCalendar` 只消费状态。改造前补任务页快照/交互基线（6 周、周一、补位不可点、高度 280、selected 外部变化不切月），改造后逐项回归；note 侧只新增 loader/scope，不改变默认布局。**本期决策：两套日历（`BbMiniCalendar` 用于任务页/右栏、`useMonthCalendar` 用于全页日历）不合并**，只统一 `loader(year,month,scope?)` 签名与 `forbidden/error` 语义；"合并为单一 `useCalendar` + 薄渲染组件"列为中远期优化——它要动任务页 4 项回归 e2e，本期不做。

**NoteCalendarView scope 选择器（不含 visible，不提供）**：mine/shared/explore/internal 登录用户可选；subordinate 开关关闭→**隐藏**入口（不显示、不 403 干扰）；all 仅 ADMIN 显示（非 ADMIN 隐藏）。**日历不提供 visible scope 聚合入口（`visible` 无独立列表落地页，仅用于引用选择器搜索与列表查询值，见 后端文档 §5.3）**。

**`BbMiniCalendar`（迷你日历）note 消费方**：**`NoteHomeView` 右栏 360px = `BbMiniCalendar`（mine scope，传 note loader）+ 当日日志列表**，点日过滤 mine 当日；这是 note 侧唯一使用 `BbMiniCalendar` 的地方（全页日历另用 `useMonthCalendar`）。**右栏"当日日志"唯一实现（不再保留备选口径）：`useNoteList({ isolated:true, isolatedKey:'home-side', initialQuery:{ date: 今天, page:1, size:5 } })`，渲染走 `NoteMiniList`**——不共享主列表的 `page/query`，点日历只改右栏当日结果，主列表筛选/页码不受影响。**右栏选中日期不写 URL、不跨刷新保留**（隔离优先，刷新回今天），不额外存 sessionStorage。`useNoteList` 契约定义：

```ts
interface UseNoteListOptions { isolated?: boolean; isolatedKey?: string; initialQuery?: NoteQueryPatch & { page?: number; size?: number } }  // initialQuery 仅在**初始化**时生效（允许 page/size；初始化后页码由 `setPage` 单点写，`setQuery` 运行时剔除 page/size 属"运行期单一入口"，二者不冲突）
interface UseNoteListResult {
  notes: NoteBrief[]; total: number; page: number;
  loading: boolean; error: Error | null;
  query: ComputedRef<NoteQuery>;                     // 当前查询参数（只读）
  setPage(page: number): void;                       // 写下一页 → 内部写 URL + 重新请求
  setQuery(patch: NoteQueryPatch): void;             // 更新筛选/排序等（内部重置 page=1）+ 写 URL + 请求（类型收窄）
  resetPage(): void;                                 // 只改 state（page=1），不发请求；需重拉第一页用 reloadFirst
  reloadCurrent(): void;                             // 按当前条件重拉、不改页码（refresh 语义）
  reloadFirst(): void;                               // 重置 page=1 + 重拉第一页（重拉语义）
  refresh(): void;                                   // 等同 reloadCurrent（保留别名，兼容旧调用；useNoteActions.refresh 调此，不改页码）
  **needsReload: ComputedRef<boolean>;               // cache 命中且 page > totalPages 时派生为 true（**纯计算、不可赋值、不存在"清零"**）；**`watch` 主体唯一**：由 `useNoteList` 内部 `watch(needsReload, v => v && reloadFirst())` 自动重拉（非 isolated 实例只此一处，7 页不重复 watch、也不会无人监听），成功后 page=1 且换新数据 → 派生值自然变 false；用于区分"正常空页"与"需要重载"**
}
```

**分页/筛选写入约定**：`NoteList` 的 `page-change(page)` → `setPage(page)`（内部写 URL `?page=` + 重新请求，返回后仍停在该页）；筛选器变更 → `setQuery({...})`（内部**重置 `page=1`** + 写 URL + 请求）；**`resetPage()` 只改 state（page=1）不发请求**；**`reloadCurrent()` 按当前条件重拉、不改页码**；**`reloadFirst()` 重置 page=1 + 重拉第一页**；`refresh()` 是 `reloadCurrent()` 的别名（保留兼容旧调用）；`query` 只读供 UI 展示，**页面不直接改 `stores/note` 的分页/筛选字段**——`useNoteList` 是分页/筛选/URL 同步/竞态取消/缓存读取的唯一入口，避免 7 页分叉。`isolated:true` 时**不读写 `stores/note` 的主列表状态、也不读写 URL**——只维护实例内状态（`query/page` 为局部 ref，`setQuery` 不写 `route.query`，不监听 URL 变化）；单测补"isolated setQuery 后 route.query 不变"。`setQuery` 入参类型为 `NoteQueryPatch = Omit<Partial<NoteQuery>,'scope'|'page'|'size'>`（运行时剔除 scope/page/size，防绕过 route.meta 和分页单一入口）。`useNoteActions()` 的 `onChanged` 默认调 `reloadCurrent()`，删除/归档导致当前页空时 `clamp page`（`page > totalPages` → `setPage(max(1,totalPages))`，请求返回后若 `page > totalPages` 再 `setPage(max(1,totalPages))`，**用 `clamping` 标记（`useNoteList` 内 `ref<boolean>`）保证只 clamp 一次、不递归**）。`setPage` 本身即发请求，因此 **clamp 后必然重拉，不需要额外 `reloadCurrent()`**。右栏"当日日志"用独立 `NoteMiniList`（固定 5 条、无分页、底部"查看全部"跳主列表，见 §7.10 组件契约），**不复用 `NoteList`**（避免 pageSize=5 与固定 20 冲突）；`useNoteList({ isolated:true, initialQuery:{ date: today, page:1, size:5 } })`仍用于右栏数据请求，但渲染走 `NoteMiniList` 而非 `NoteList`。`NoteList` loading/error/empty 优先级：首次加载 loading > error > empty > 列表；刷新时保留旧列表 + 顶部错误条。

- **上传签名（以 §7.7/§6 `file.ts` 为准，本节不重复定义）**：通用 `POST /files` 拒绝 `taskId`（非空→400），故 `uploadFile` 不带 `taskId` 参数——统一签名 **`uploadFile(file, opts?)` / `uploadTaskFile(taskId, file, opts?)`（`opts={onProgress,signal}`）**；`BbAttachmentList` 用 `uploadTaskFile(taskId, file, opts?)`、note 上传用 `uploadFile(file, opts?)`，不得再传 `taskId`（否则撞 400）。
- **`log_date` 前端口径（一律字符串）**：只按 `YYYY-MM-DD` 字符串处理；`el-date-picker` 用 `value-format="YYYY-MM-DD"`；**禁止 `toISOString()`** 与 `new Date('YYYY-MM-DD')`（UTC 解析会跨日）；日期比较用字典序；日历分组、`date=` 查询、`start/end` 范围三处同口径；`utils/date.ts` 只用于任务 `dueAt/remindAt`，不混用到 `log_date`。**"今天"唯一取法**：`todayInTz('Asia/Shanghai')`＝`new Intl.DateTimeFormat('en-CA',{timeZone:'Asia/Shanghai'}).format(new Date())`（输出即 `YYYY-MM-DD`），右栏 `initialQuery.date`、编辑器 `logDate` 默认值、临时卡片均复用该函数，**禁止 `toISOString().slice(0,10)`**。补 23:59/00:00、月末、跨年、UTC+13 时区用例。
- **`scope=subordinate` 403 空态**：`errorCode.ts` **补齐 5xxxx 全部码**（文案统一"工作日志"）；后端 `scope=subordinate` 开关关闭时返回 **HTTP 403**（不返回 `ApiResult` 业务码），故**前端不按 `code===50016` 分支**（该分支不可达，50016 仅作后端日志/审计用）；`NoteSubordinateView`/`useNoteList` 改为**捕获 `err.status===403 && route.meta.scope==='subordinate'`** 渲染**页面空态**"下属日志功能未开启，请联系管理员"，**不 toast**。`UserVO.managerCanReadSubordinate: boolean`（随登录用户信息返回，**唯一方案**；不设 `GET /users/me/features` 之类旁路接口）；导航项按 `user.managerCanReadSubordinate` 隐藏。`scope=subordinate` 开关关闭时**对所有人返回 403（包括 ADMIN）**——前端导航对 ADMIN 也按 `managerCanReadSubordinate=false` 隐藏（不例外放行）；同步 后端文档 §5.1、§5.2、§9 Row 12a（ADMIN 无例外）。
- **`BbTagPicker` 标签来源与选中值契约**：`BbTagPicker` **只接受 `options?: TagOption[]` props、不依赖 store**，并**暴露选中值契约：`props { options?: TagOption[]（由 `TagVO[]`映射为`TagOption[]`）; modelValue: number[]（已选 tagIds）; disabled?: boolean }` + `emits { 'update:modelValue': [value: number[]] }`——父组件用 `v-model` 双向绑定已选标签**；**标签选择是多选（数组模型，可选多个/清空为空数组），非单选**；`NoteEditor` 用 `v-model` 把 `tagIds` 绑到 `BbTagPicker`——编辑态初值来自 `note.tags.map(t=>t.id)`、创建态为 `[]`；`NoteEditor` 传 `note.ownerTags ?? props.ownerTags` 给 `options`（编辑态详情优先，创建态用 `props.ownerTags`=metaStore.tags；**`TagVO[]`→`TagOption[]` 的映射职责在 `NoteEditor` 内**（`{id,name,count}` 原样映射后传），`BbTagPicker` 只认 `TagOption[]`、不认 `TagVO[]`；**`ownerTags` 为 `undefined` 时可合法省略/传 `undefined` 给 `options?:`**）；**三态区分**——清空全部标签 → `modelValue=[]`（保存后请求体 `tagIds: []`，**不被当作"未修改"**）、无标签用户可保存空数组、**`options/ownerTags === undefined`（未加载）才告警并禁用保存——**三态以 `options` 为准**：`undefined`=未加载（禁用）、`[]`=确实没有标签（可保存）、非空（可保存）**，避免把"空数组"误判为"未加载"（见 §7.2 单一引用，不再写"缺失但 canEdit=true 时禁用"的旧口径），避免静默丢标签（ADMIN 编辑他人日志能看到 owner 的标签并正确回显）。
- **预览/下载浏览器细节**：抽 `openAttachment({ mode:'download'|'preview', url, fileName, contentType })` 统一处理——(1) **签名增加 `contentType` 参数**（用于 MIME 白名单校验）；(2) **noopener**：`window.open('', '_blank', 'noopener')` 返回 `null` 无法赋 `location`，**统一用 `window.open(blobUrl, '_blank', 'noopener,noreferrer')`** 打开（该三参写法在 Chrome/Edge/Firefox 均可用，返回句柄或 `null` 都不影响打开；返回 `null` 时按"无句柄预览"处理，revoke 交由 blobCache 的条目上限兜底）。**禁止**"`window.open('')` 再赋 `location`"的两段式写法——它无法带 `noopener`，会留下 `window.opener` 篡改风险；预览窗口关闭时 `beforeunload` revoke；(3) **路径安全校验**（原称"同源校验"，名不符实故改名）：只接受相对路径，拒绝 `^[a-z]+://`、`//`、`..`、反斜杠、`javascript:`、`data:`；若调用方传入绝对 URL，必须与 `location.origin` 同源才放行（不同源直接拒绝）；(4) **文件名三级回退**：`filename*`（RFC 5987 中文编码）→ `filename`（普通）→ `fileName`（前端兜底）；(5) **MIME 白名单**：仅 `image/png|jpeg|gif|webp`、`application/pdf`、`text/plain` 可内联预览；`text/html`/`image/svg+xml` **一律仅下载、绝不开新窗预览**（html 可转义为纯文本展示，svg 不提供任何内联/预览入口）（blob URL 继承应用源，HTML/SVG 中的 `<script>` 可读同源 localStorage）；Office 只下载（fallback）；(6) **引用计数管理**：集中到 `attachmentBlobCache`——`acquire(key)` 返回 blob URL 并 +1 计数、`release(key)` -1 计数、计数归零时 revoke；组件 `onUnmounted` 调 `releaseAll()`；下载在 `a.click()` 后 `setTimeout(revoke, 1000)`；预览**只在窗口关闭（`beforeunload`/`pagehide`）或引用计数归零时 revoke，不做 60s 硬超时**（固定超时会在用户阅读中途把 blob 撤销）；窗口句柄不可得时按 `attachmentBlobCache` 条目上限（20）LRU 回收，而非按时间；被拦截时**降级为下载并提示**；大文件内存整块 `Blob` 加大小上限提示。
- 纯文本 `white-space: pre-wrap`，禁 `v-html`；`Ctrl+Enter` 判 `isComposing`。

**NoteAttachmentList 权限表**（上传按钮以 `note.canEdit`（含归档 `isWritable`）驱动，**不按角色直判**）：

| 角色             | 未归档上传 | 归档上传 | 移除关联 |
| -------------- | ----- | ---- | ---- |
| owner          | 是     | 是    | 是    |
| EDITOR         | 是     | 否    | 否    |
| ADMIN          | 是     | 是    | 是    |
| VIEWER / 其他可见者 | 否     | 否    | 否    |

> **按钮口径**：上传=`note.canEdit`（归档时 EDITOR `canEdit=false`）；移除关联=**`NoteAttachmentVO.canRemoveRef`**（owner/ADMIN）。**`canDelete`（物理删）与 `canRemoveRef`（移除关联）在 UI 分开**：EDITOR 自己上传的文件 `canDelete=true` 但 `canRemoveRef=false`，此时不出现"移除"按钮（`v-if="item.canRemoveRef"`）。

> **上传下载链路**：上传 `uploadFile(file, opts?)`（`taskId=null`，见 §7.7 签名）先得 `FileVO`（此时无 noteId，仅用于临时展示）→ **再 `POST /notes/{id}/attachments` 关联**、**该响应返回完整 `NoteAttachmentVO`（含 note 专用相对路径 `downloadUrl`：`/notes/{noteId}/attachments/{attachmentId}/download`，配合 `http.baseURL='/api/v1'` 使用，不带 `/api/v1` 前缀）**，前端**以该响应的 `NoteAttachmentVO` 替换刚 push 的临时项**为最终展示。
>
> **删除关联按钮**：由 **`NoteAttachmentVO.canRemoveRef`（或 `NoteVO.canManage`，owner/ADMIN）** 控制，**不使用 `FileVO.canDelete`**（那表示"可物理删除文件"）。EDITOR 上传的 note 附件对 owner：`canDelete=false` 但 `canRemoveRef=true` 可移除关联；对 EDITOR 自身：`canDelete=true` 但 `canRemoveRef=false` 不可移除关联——按钮据此正确显示。
>
> **失败处理与幂等**：
>
> - **`POST /notes/{id}/attachments` 幂等**：关联已存在（`UNIQUE(note_id, attachment_id)` 冲突）→ **返回现有 `NoteAttachmentVO`，不 409**；前端 POST 成功但未收到响应时重试，不会重复上传/报错。
> - 关联调用失败 → 前端**回滚已上传文件**（尝试删除刚上传附件记录/文件，不残留孤儿）。
> - **回滚删除附件失败**：记录日志并提示"附件已上传但关联失败"（**不静默吞掉**），交由 `FieldCleanupJob` 孤儿清理兜底。
> - **删除关联失败时保留列表项**并提示（不本地移除）。

> 日历点日跳转写 `/notes/{scope}?date=`，但 mine 的实际路由是 `/notes`（非 `/notes/mine`，项目无该路由）。抽取 `noteListRouteOf(scope: NoteScope | 'archived'): string`（`archived` 不属于 `NoteScope` 的 7 个 scope，参数需显式并入以避免 TS 不可比较）——`mine → '/notes'`、`explore → '/notes/explore'`、`shared → '/notes/shared'`、`internal → '/notes/internal'`、`subordinate → '/notes/subordinate'`、`all → '/notes/all'`、`visible → '/notes'`（visible 无独立路由，fallback mine）、`archived → '/notes/archived'`（`archived` 不属于 `NoteScope`，由调用方显式传 `'archived'`）；日历 `select-date` 跳转用 `router.push({ path: noteListRouteOf(scope), query: { date } })`；补单测"7 scope 点日跳转路由正确"；**`archived` 仅供归档页调用**，日历 6 scope 永不传入，补单测固化该边界。

**DTO 字段**：

- `NoteVO`：`id/content/**contentSummary**/logDate/visibility/pinned/archived/ownerId/ownerName/ownerDept/**version**/canEdit/canManage/grantRole/createdAt/updatedAt/tags`（tags=本 note 已选；**NoteVO 自身不含 ownerTags**）。**`contentSummary` = 后端固定字符摘要（如 ≤200 字，含换行信息），列表/映射摘要一律取它，前端不自行 `slice` 截断**。
- `ownerTags`：owner 完整标签 `[{id,name}]`——**只出现在 `NoteDetailVO`**（`NoteVO`/`NoteBrief` **均不含**），且**仅 `canEdit==true || canManage==true` 时返回**；列表不返回 ownerTags（口径唯一，避免三处不一致）。
- **返回类型约定**：`GET /notes` → **`PageResult<NoteBrief>`**（列表只给摘要，不给全文，控制首屏体积）；`GET /notes/{id}`、**创建 `POST /notes`、更新 `PUT /notes/{id}` → `NoteDetailVO`**（创建/更新后立即拥有全文/ownerTags/attachments/relations，便于内联展开附件区、重置标签选择器）。**保存成功后返回的 `NoteDetailVO` 仅用于临时"刚创建"卡片与详情展示，不插入/更新列表（列表统一走"保存后重拉第一页"）**。OpenAPI 对创建/更新/详情统一一个 `200` schema，**`NoteDetailVO extends NoteVO`**（继承关系写清，避免三处口径冲突）。`NoteBrief` 与 `NoteCard` 字段一一对应。
- `NoteBrief`：`id/contentSummary/logDate/visibility/pinned/archived/ownerId/ownerName/tags/canEdit/**canManage**/version`（**字段名 `contentSummary`，与 `NoteVO.contentSummary` 同名同义；`NoteBrief` 不含 `content`（全文）字段**，杜绝"详情全文/列表摘要同名字段误用"；**摘要算法：后端取 `content` 前 200 码位（保留换行、不足不补省略号）生成 `contentSummary`，前端不二次截断**）。**列表与详情同口径**：**编辑内容**=`canEdit`（`canEdit` 已含 `!deleted` 与"归档 EDITOR=false、归档 owner/admin=true"规则，**不再叠加 `&& !archived`**）；**置顶/归档/删除（pin/archive/delete）**=`canManage`（owner/ADMIN，EDITOR=false、管理员可管他人日志）；**标签编辑**=`canManage`（EDITOR 禁止）。前端 `NoteCard` 按钮据此渲染，**禁止 `canEdit` 控管理按钮、禁止 `ownerId===me` 推导**（否则 ADMIN 无法管理他人、EDITOR 误显删除会 403）。
- **卡片按钮矩阵（e2e 六身份）**：owner 全显（编辑/置顶/归档/删除，**含归档态仍可编辑**）；EDITOR 仅编辑（`canEdit=true`，管理按钮不显示；**归档态 EDITOR `canEdit=false` 编辑也隐藏**）；VIEWER 只读；ADMIN 全显（即使非 owner，含归档态）；归档 owner/ADMIN 均保留编辑入口（`canEdit` 已含此规则）。
- `grantRole`：VIEWER/EDITOR/OWNER/ADMIN/null=无授权。
- **`NoteUserGrantVO`**（`GET /note-grants` 的元素，由 `tab` 参数区分 created/granted/incoming/all）——授权页按此渲染列与按钮：
  ```text
  id, grantorId, grantorName, granteeId, granteeName
  role        // VIEWER | EDITOR
  status      // PENDING | APPROVED | REJECTED | REVOKED
  mode        // OWNER | SUPERIOR | ADMIN
  direction   // outgoing(grantor_id==me) | incoming(grantee_id==me) | **none**（两者皆非，如 ADMIN 代授权行对 ADMIN；纯粹行内展示，不参与 Tab 过滤）
  createdBy, createdByName, createdAt
  approvedAt, approvedBy, revokedAt, revokedBy
  canApprove  // 待我处理（grantor==me 确认他人发起的 PENDING，出现于 granted 的 PENDING 行）
  canReject   // grantor==me 可拒 PENDING
  canUpgrade  // VIEWER→EDITOR（仅 APPROVED 且 grantor==me）
  canRevoke   // 撤 PENDING：grantor==me OR created_by==me 或 ADMIN；撤 APPROVED：grantor==me 或 ADMIN（grantor 对 granted 的 PENDING 亦可撤回；ADMIN 仅对 PENDING/APPROVED 有"撤销"语义，REJECTED/REVOKED 无）
  ```
  **action 口径**：`can*` 均由后端按「当前用户 + 该行」计算下发，前端只读不推导；**具体按钮按 §7.5 按钮矩阵（含 Tab 维度限制）渲染，`can*` 与矩阵并存、矩阵更细**。**SUPERIOR 行 grantor（下属 A）确认/拒绝**，`approved_by=grantor`，A 经 `tab=granted` 始终可见并可撤销/升级，**granted 的 PENDING 行可"确认/拒绝/撤回"**；**发起人 S 可撤回自己发起的 PENDING**（`created_by==me`）。ADMIN 全量视图（`tab=all`）只读列表 + 可代撤销（对 PENDING/APPROVED 任意行；REJECTED/REVOKED 只读）；ADMIN 在 `tab=created` 只对本人发起行可代撤销——`grantor==me` 可升级/撤销，`isAdmin && created_by==me`（ADMIN 代授权行）可撤销不可升级。`GET /note-grants` 仅一个端点，`tab` 参数覆盖 created/granted/incoming/all，**不再有独立 `/pending`、`/all` 端点**。
- **`NoteAttachmentVO`**（`POST /notes/{id}/attachments`、`GET /notes/{id}/attachments` 的元素）：
  ```text
  id            // 关联 id（note_attachment_ref.id）
  attachmentId  // 附件 id
  fileName, size, contentType
  downloadUrl   // 相对 baseURL 路径，如 /notes/{noteId}/attachments/{attachmentId}/download（不带 /api/v1）
  createdBy, createdByName, createdAt
  canRemoveRef  // owner/ADMIN 可移除关联
  canDelete     // 可物理删（上传者/ADMIN）
  ```
  **`NoteAttachmentVO.createdAt/createdBy` = 附件上传时间/上传者**（取自 `attachment` 表，**非关联时间**；UI 文案统一"上传者/上传时间"，见 §7.7）。

  前端以 `POST /notes/{id}/attachments` 返回的该 VO 替换临时 `FileVO` 起最终展示（`NoteAttachmentVO.id` 是关联 id，**删除传 `attachmentId`**）。
- **`NoteRelationVO`**（`GET /notes/{id}/relations`——"我引用了谁"的元素，填充 **target** 字段）：
  ```text
  id            // note_relation.id，删除用
  targetType    // NOTE | TASK
  targetId
  targetSummary // NOTE 取 contentSummary / TASK 取 title
  createdAt, createdBy, **createdByName**   // 引用时间/引用人（UI 显示"引用人：张三"）
  // 不可见 TASK 目标直接不返回，不要 targetVisible=false 占位
  ```
- **`NoteBacklinkVO`**（`GET /notes/{id}/backlinks`——"谁引用了我"的元素，填充 **source** 字段；`note_relation` 行语义是 `source → target`，backlinks 查 `target=当前note` 的行，故需来源侧字段，与 relations 的 target 语义不同，**不可复用 `NoteRelationVO`**）：
  ```text
  relationId           // note_relation.id
  sourceNoteId         // 来源 note id（点击跳 /notes/{sourceNoteId}）
  sourceSummary // 来源 note 摘要
  sourceOwnerId, sourceOwnerName
  createdAt, **createdBy, createdByName**   // 引用时间/引用人（EDITOR/ADMIN 也可添加引用，"引用人"≠来源 owner；可空显示"—"，与 NoteRelationVO 口径一致）
  // 来源 note 不可见/已删除 → 整条不返回（不占位，不泄露）
  ```
- **`NoteDetailVO`**：`...NoteVO + relations: NoteRelationVO[] + backlinks: NoteBacklinkVO[] + attachments: NoteAttachmentVO[] + ownerTags?: TagVO[]`（有权限时）。
- **`FileVO` / `TaskVO.files`**：附加 `downloadUrl`（**上下文相关、可空、相对 baseURL**——通用 `/files` 上传返回 `/files/{id}`；task 上传返回 `/tasks/{taskId}/attachments/{id}/download`；**仅作路径引用，不做 `<a href>` 直链**）、`createdBy`、`canDelete`（**可否物理删**，创建者/ADMIN，**不含引用保护**）、`canRemoveFromTask`（**task 附件删除按钮口径**，=`assertWritable && (createdBy==me||isAdmin)`；由后端按当前用户+当前 task 计算）。task 附件删除走 `DELETE /tasks/{taskId}/attachments/{id}`。

**前后端契约固化**：上述 VO 字段表写入 OpenAPI，`types/api.d.ts` 由 OpenAPI **重新生成**、**禁止手写 `any` 兜底**；`NoteBrief`/`NoteAttachmentVO`/`NoteRelationVO`/`NoteBacklinkVO`/`NoteDetailVO`/`NoteUserGrantVO` 的 TypeScript 类型为契约来源。

**新建/筛选器归属**：**方案 A（页面 owns 交互）**——`NoteListView` 是**布局壳**、**内部渲染 `NoteList`（壳内渲染）+ 壳内渲染 `NoteFilterBar`**，提供 **`#composer` / `#above-list` / `#editor` 具名插槽**、**不内部实例化编辑器、不持有保存/附件状态**；**壳把 `notes/loading/error/page/total/emptyText`（`activeId`，页面可把当前选中卡片 id 传进来，壳原样透传给内部 `NoteList`）透传给 `NoteList` 并显式透传 `open/edit/pin/archive/unarchive/delete/page-change/retry` + `change` + `retry-tags`（共 10 个事件，与 §7.10 契约表一致；`change` 透传 NoteFilterBar 筛选变更，`retry-tags` 透传标签 facet 重试）**，页面只传数据 + 监听事件（7 个 scope 页统一走此装配，杜绝每页自写一套 NoteList/事件绑定）；`NoteHomeView` 自己持有 `NoteEditor`（经 `#composer` 插槽放入新建、经 `#editor` 插槽放入行内编辑宿主）、`POST /notes`、保存后清空筛选+重拉、临时卡片附件区状态。壳内 `v-if="route.meta.scope==='mine' && !route.meta.archived"` 才渲染 `#composer`/`#above-list` 插槽；**`NoteListView`/`NoteList` 不接收 `scope`/`archived` props，统一读 `route.meta`**。**新建入口仅 `mine`（NoteHomeView）提供**（`all` 不提供新建：它是管理视图，新建后归属/可见性易混淆；`explore/shared/internal/subordinate/archived` 不提供新建）。**筛选器（`filterConfig`）全员提供**（搜索/标签/排序/置顶/date，`NoteFilterConfig` 见 §7.10）。**`NoteList` 的 `open/edit/pin/archive/unarchive/delete` 事件由页面在外层处理（壳透传，不在壳内吞掉）；此项动作逻辑抽入公共 `useNoteActions()`——open 跳详情、edit 先 `GET /notes/{id}` 拉详情后**回调 `onOpenEditor(noteDetail)`**（方案 A：页面经 `#editor` 插槽承载 `NoteEditor` 宿主）、pin/archive/unarchive/remove 调 API、刷新与 toast 均由它承载，7 个 scope 页共用同一 composable、只注入 scope 差异（见 §7.10），杜绝 7 份复制**。

**7 个 scope 页的"最小模板"**（**"≤12 行"指 `<template>` 部分**，`<script setup>` 装配 composables 另计约 10-15 行；模板出现第 13 行就说明该逻辑应下沉到 `NoteListView`/`useNoteList`）：

| 页面 | scope（meta） | `filterConfig` | `emptyText` | 特有分支 |
| --- | --- | --- | --- | --- |
| NoteHome | mine | 全 true | 暂无日志，点击上方开始记录 | `#composer`/`#above-list`/`#editor`（**唯一行内编辑宿主**） |
| NoteExplore | explore | `pinned:false` | 暂无公开日志 | edit 跳详情；无编辑器 |
| NoteShared | shared | `pinned:false` | 暂无被授权给我查看的日志 | — |
| NoteInternal | internal | `pinned:false` | 暂无本部门日志 | 无部门时同样用该空态 |
| NoteSubordinate | subordinate | `pinned:false` | 下属日志功能未开启，请联系管理员 | `errorMode='empty'` + `isScopeDisabled403` |
| NoteAll | all | `pinned:false` | 仅管理员可查看 | `errorMode='empty'` + 守卫 + 403 兜底 |
| NoteArchived（两路由） | mine/all + archived | `dateRange:false`、`pinned:false` | 归档区暂无日志 / 暂无全部归档日志 | 按 `meta.scope` 切文案与分段 |

```vue
  <NoteListView v-bind="listBind" :filter-config="CONFIG" empty-text="暂无本部门日志"
    @open="actions.open" @edit="actions.edit" @pin="actions.pin"
    @archive="actions.archive" @unarchive="actions.unarchive" @delete="actions.remove"
    @page-change="list.setPage" @retry="list.reloadCurrent"
    @change="list.setQuery" @retry-tags="facets.retry" />
</template>
```

**三级调用链（唯一路径，禁止直连）**：`NoteCard` 按钮 → `NoteList`（转发）→ `NoteListView`（透传 emit）→ 页面 handler（`useNoteActions.*`）：

```
Card: @delete  ──▶ NoteList emit delete(note) ──▶ NoteListView emit delete(note) ──▶ page: actions.remove(note)
Card: @edit    ──▶ NoteList emit edit(note)   ──▶ NoteListView emit edit(note)   ──▶ page: actions.edit(note)
                                                                                    └─ mine: GET detail → onOpenEditor(detail)
                                                                                    └─ 其余: router.push('/notes/{id}')
```

> 壳本身**不持有任何业务状态、不发起请求**；`useNoteActions` 只被页面调用，`NoteListView` 不认识它。

> 除上表"特有分支"外，**页面内不得出现任何 if/else 业务判定**——**配置数据差异允许（`filterConfig`/`emptyText`/`errorMode` 属传参），条件分支禁止**；7 页的差异必须是"配置数据"，不是"代码分支"。

### 7.2 新建/编辑流程与 `NoteEditor` 契约

- **新建入口**：`NoteHomeView` 顶部内联编辑器（仿 `BbTaskComposer`，非独立页非弹窗），经 **`NoteListView` 的 `#composer` 插槽**渲染；`NoteHomeView` **持有 `NoteEditor` 与保存/附件状态**，负责 `POST /notes`、保存后清空筛选+重拉、临时卡片管理等全部交互——`NoteListView` 不接编辑器的保存事件。
- **新建默认值**：**创建默认值只在 `NoteEditor` 内部定义一次**（`logDate=今天（Asia/Shanghai）`、`visibility=PRIVATE`、`tagIds=[]`）；`NoteHomeView` 不重复传（仅在其行为需覆盖时传可选覆盖）。前端先行，不依赖后端默认（`INTERNAL` 无部门时前端预提示——**触发时机：用户把 visibility 切到 INTERNAL 时即时提示并禁用保存**，文案与后端 50017 一致："当前账号无部门，无法设为本部门可见"；**不得默认 PUBLIC**）。
- **保存行为与"新建后状态机"（方案 A：临时卡片 + 落点固化）**：`NoteHomeView` 保存成功后：**(a)** `POST /notes` 返回 `NoteDetailVO`（含 id）；**(b)** 在列表顶部保留一张**临时"刚创建"卡片**（含 `noteId` + 附件区 `NoteAttachmentList` + "完成" + **"放弃"**按钮），**独立于列表数据、不随重拉消失**；**(c)** 同时**清空关键词/标签/置顶/日期筛选**、**按当前排序重拉第一页**并 toast"已保存并回到第一页"（**"新建后回第一页"是明确预期**，即使在看第 3 页；列表数据照常刷新；若新日志恰在第一页，临时卡片与列表卡片并存——列表卡片无附件入口，附件以临时卡片为准）；**(d)** 用户在临时卡片内完成附件上传/关联，点"完成"或"放弃"或开始输入下一条时移除临时卡片。**不"跳 logDate 所在页"、不在列表本地插入、不做无条件 unshift。** 保证：新日志即使不在第一页，用户仍有明确入口补附件；输入框清空、焦点保留（开始下一条时先完成/放弃第一条，防止附件状态串条）。

  **临时卡片落点与跨路由恢复**：临时卡片经 **`NoteListView` 新具名插槽 `#above-list`** 渲染（仅 `route.meta.scope==='mine'` 且非 archived 时渲染，与 `#composer` 同条件；= 编辑器与临时卡片各占一槽，避免同槽职责混杂、组件契约闭合）；`NoteHomeView` 把**临时卡片 noteId 写入 `stores/note.pendingCreatedNoteId`**（持久化到 sessionStorage），**进入详情再返回 `/notes` 或同 scope 刷新时恢复临时卡片**（`onMounted` 读 `pendingCreatedNoteId` 重建；**恢复失败（404 已删除/无权）时只 toast"刚才创建的日志已不存在"，不渲染任何补附件入口，并立即 `clearPendingCreated()` 删掉 sessionStorage key**——否则每次进页都会重试恢复、反复 toast；半成品卡片比没有更糟）；新日志已不在第一页时，经恢复的临时卡片仍是明确附件入口。"放弃"按钮 = 移除临时卡片（不回滚已创建的 note，仅放弃当前补附件/展示）。
- **行内编辑先取详情**：列表卡片内容点击（**`canEdit`** 即可，`canEdit` 已含归档 EDITOR=false/owner-admin=true，**不叠加 `!archived`**；管理动作 `canManage`）→ 先调 `GET /notes/{id}` 拿 **`NoteDetailVO`（全文 + ownerTags + version）** 再打开 `NoteEditor`，加载期间卡片级 skeleton；**绝不把 `NoteBrief` 的摘要当编辑器全文**（否则保存会把全文截短且不可恢复）。`VERSION_CONFLICT` → 见 §7.9。ADMIN 行内编辑他人日志同样走详情（拿 owner 标签），故 `ownerTags` 有值可回显。**宿主规则（唯二，不再扩展）**：只有 `NoteHomeView`（mine）提供行内编辑宿主（`#editor`）；其余 6 个列表页的 `edit` 一律 `router.push('/notes/{id}')` 跳详情内编辑——`useNoteActions.edit()` 因此按"页面是否注入 `onOpenEditor` 回调"分流，不注入即跳详情。**detail 复用**：页面级 `useNoteDetail` 已加载同 id 时直接复用，不重复 `GET`，列表行内编辑也不新建第二个实例。**`notFound` 渲染**：`useNoteDetail.notFound===true` 时页面渲染 `NoteNotFound` 空态组件（替换正文、不显示重试按钮、不改标题）；**复用实现**：`useNoteDetail` 不做全局缓存——`NoteHomeView` 与 `NoteDetailView` 各自在 `setup` 顶层持有一个实例，同页面内行内编辑复用，跨页面靠重新 `GET` 拉取（次数可控、语义最简单）。**收敛单点**：详情内一切改动只经 `useNoteDetail.reload()` 整体收敛，附件/引用子组件不做局部 append/merge（消除"全量 reload 与增量 changed 竞态覆盖"）。
- **`NoteEditor` 契约（单受控源；字段只初始化一次；含 `ownerTags?`）**：**props 契约以 §7.10 可辨识联合为准**（`{ mode:'create' } & { modelValue; ownerTags?; saving; maxLength?; fieldPermissions?; hasDept } | { mode:'edit' } & { modelValue; note: NoteDetailVO; ownerTags?; saving; maxLength?; fieldPermissions?; hasDept }`——TS 编译期阻止 `mode='edit'` 不传 `note`；`maxLength?` 可选默认 20000；`fieldPermissions?` 编辑态从 `note.canManage` 派生；`hasDept` 必填）。`emits { (e:'update:modelValue', v: string), (e:'save', payload: NoteSavePayload), (e:'cancel'), (e:'draft-change', v: NoteDraft) }`（**`NoteSavePayload` 为可辨识联合：`{ mode:'create'; content; logDate; visibility; tagIds } | { mode:'edit'; content; logDate; visibility; tagIds; version:number }`——创建态**绝不发送 `version`**（`NoteCreateReq` 无 version 字段，避免前端类型为 number 但运行时 undefined/误传）；编辑态必带 `version`。调用方按 `payload.mode` 分派到 `POST /notes` / `PUT /notes/{id}`**。`NoteDraft = { noteId?: number; content: string; logDate: string; visibility: NoteVisibility; tagIds: number[]; version?: number; updatedAt?: string }`——`noteId/version/updatedAt` 改为可选（创建态无 noteId/version；`draft-change` 事件只在 `mode='edit'` 发出，创建态不发 `draft-change`；编辑态 `noteId/version/updatedAt` 必填）。**内容只来自 `modelValue`**（唯一受控源，`v-model` 实时同步）；`note` 仅在 `mode:'edit'` **初始化时读取一次全部可编辑字段**：`content→modelValue 初值 + logDate + visibility + tagIds(= `note.tags.map(t=>t.id)`) + version + ownerTags`（`NoteDetailVO` 只有 `tags: TagVO[]`，无 `tagIds` 字段；初值统一为 `note.tags.map(t=>t.id)`）；5 个需渲染/保存字段 `content/logDate/visibility/tagIds/version` 的初值全部来自 `note`，无一处落到组件默认值）。**note 切换语义**：**区分"同一 note 的异步刷新"（`note` 变化不覆盖）与"切换到另一 note"（必须重置）**——父组件只用 `:key="note.id"` 强制重建编辑器（**`mode` 运行期禁止切换**：创建态↔编辑态必须重新挂载，不允许同一实例改 `mode`；`create→edit` 亦走 `:key`。**`:key` 由父组件提供**：`:key="`${mode}:${note?.id ?? 'new'}`"`），不使用 `watch(() => note.id, ...)`**——`watch` 会在 note 切换时保留旧组件实例，字段初始化顺序不确定；`:key` 强制重建确保字段初值全部来自新 note。**避免点卡片 A 再点 B 时继续显示 A 内容、保存把 B 覆盖成 A**；仅同一 note 的刷新（version 变化）由父组件控制不换 `:key`，不重置用户输入。**编辑态只接受 `NoteDetailVO`，不接收 `NoteBrief`**（否则 `logDate/visibility/tagIds` 因 `NoteBrief` 字段缺失/口径不同而静默重置，属数据损坏）。**创建态（`mode:'create'`，`note` 为空）默认值由前端先行设定，不依赖后端默认**：`logDate=今天（Asia/Shanghai，本地取日前禁用 `toISOString()`，见 §5.1 log_date 口径）`、`visibility=PRIVATE`、`tagIds=[]`——据此前端可预校验"visibility=INTERNAL 但无部门"（后端 `NOTE_DEPT_REQUIRED/50017` 兜底）；**严禁默认 `visibility=PUBLIC`**（会把工作日志误公开）。**`ownerTags` 来源优先级**：编辑态 `note.ownerTags ?? props.ownerTags`（详情有 owner 标签优先用详情，Admin 编辑他人不回显自己的标签）、创建态只用 `props.ownerTags`（`metaStore.tags`）。**`tagIds` 经 `BbTagPicker` 的 `v-model` 双向绑定**：编辑态初值取 `note.tags.map(t=>t.id)`、创建态 `[]`；`ownerTags/options === undefined`（未加载）才告警并禁用保存（防静默丢标签）；**空数组是合法值**——显示"暂无标签"并允许保存无标签日志；清空全部标签 → `tagIds: []` 照样随 `save` 提交（**不被当作"未修改"\*\*，见 §7.10 `BbTagPicker` 三态）。`Ctrl+Enter` 保存须判 `isComposing`。
- **标签数据源接入**：note 侧必须显式加载当前用户标签，**不能依赖"先访问任务页才触发 `metaStore.loadTags()`"的隐式链路**。约定：`NoteHomeView`（或 `NoteListView` 的 note 初始化）`onMounted` 调 `metaStore.loadTags()`（已有 `tags.length` 缓存判断，重复调用零成本；也可放 `DefaultLayout` 的 `route.meta.module==='note'` 分支统一加载，避免逐页重复）；`NoteDetailView` 编辑他人日志**优先用详情 `ownerTags`**，详情未返回且 `canEdit` 时再 `loadTags()` 兜底。创建自己的日志/编辑自己日志用 `metaStore.tags`。补 e2e：全新会话直接进 `/notes` 标签下拉有当前用户标签、无标签用户可保存空标签、ADMIN 编辑他人日志回显 owner 标签。

### 7.3 列表筛选/排序/分页/URL 状态规则（`useNoteList`）

- **搜索**：顶部搜索框**回车立即触发并清除在途防抖计时器，300ms 防抖只作兜底**（二者不得各发一次请求）；**输入不足 `MIN_SEARCH_LEN`(=2，与 `/tasks/search` 共用同一常量) 字时**清空结果列表**并提示"至少输入 2 个字"，不保留上一次结果**；标签筛选**单选**下拉（mine 传 `tagId`、其余 scope 传 `tagName`——`useNoteList` 按当前 scope 决定写哪个字段，见 后端文档 §5.1）。**右栏 isolated 实例的 `date` 是右栏私有 filter**：不写 URL、不影响主列表 `date` 筛选，两者互不覆盖。
- **`date` 与 `start/end` 互斥**：UI 提供"某天"与"范围"两模式互斥 Radio，提交时二选一，后端冲突 400 不与 UI 冲突。
- **排序与置顶筛选（本期提供 UI）**：筛选区加**排序下拉**（`log_date_desc|log_date_asc|created_desc|updated_desc` 四选项，默认 `log_date_desc`）与**"仅置顶"开关**（`pinned=true`）。**scope 切换时 `queryByScope` 为每个 scope 保存独立 query，切回原 scope 时恢复该 scope 的 query（不重置、不清空）**；排序/置顶变化重置 page=1 并写入 URL；移动端折叠进筛选抽屉。
- **分页**：页码分页，**`PAGE_SIZE=20` 集中定义在 `useNoteList`/常量**（不散落），`NoteList` 收敛 `page/total` 并**用 `PAGE_SIZE` 常量算总页数**（**无 `pageSize` prop、无 `size-change` emit**）；**本期固定 20 不提供 pageSize 切换**。**页码恢复规则**：scope 变化恢复目标 scope 的独立 query（不重置 page=1、不清空筛选）；同 scope 从详情返回保留筛选与页码；**页面提供显式"重置筛选"（清空筛选并回第 1 页）**，不做"每次进入都回第 1 页"。**漏接告警（仅 dev）**：`NoteListView` 挂载时检查父组件是否绑定 `@change`/`@retry-tags`，缺失则 `console.warn`（prod 静默）——`useNoteFacets` 与列表 cache 互相独立，标签增删后不接 `retry-tags` 会一直显示旧 facet，这条告警是唯一提示。**archived 两个路由各自独立 query**（`/notes/archived` 与 `/notes/archived/all` 分开存）；**`archived` 不写 URL**（来自 `route.meta.archived`）；**隐藏字段的清理只在 `useNoteList.setQuery` 内按白名单做**，页面与 router 不各自清理。
- **scope 单一事实来源**：**列表页 scope 以 `route.meta.scope` 为唯一来源，URL 不写 `scope`（仅日历页 `/notes/calendar` 例外）**——消除"路由固定 scope / URL `?scope=` / store 缓存"三处并存冲突（访问 `/notes/internal?scope=all` 以路由 internal 为准，忽略 query scope）；`stores/note` 缓存 key 用 **`scope + query`**（不要只存一份全局筛选），同 scope 从详情返回保留、**跨 scope 也保留（各自独立 query，不清空）**。
- **URL 状态**：筛选/排序/页码写入 `query`（`?keyword=&tagId=&tagName=&pinned=&sort=&date=&start=&end=&page=`，**不含 scope**，与 NoteQueryForm/NoteQueryPatch 字段一致），刷新/分享/后退可恢复；components 由 `useNoteList` 统一读 URL 初始化。**分页/筛选全部经 `UseNoteListResult.setPage/setQuery/resetPage` 写入**——`page-change→setPage`、筛选/排序/置顶→`setQuery`（内部重置 page=1）、`refresh()` 不改页码；页面不直接改 `stores/note` 或 `route.query`（完整约定见 §4 useNoteList 契约）。**标签选中→patch 的唯一映射写在 `useNoteList.setQuery` 内部**（`scope==='mine'` → `{tagId: opt.id, tagName: undefined}`；其余 → `{tagName: opt.name, tagId: undefined}`；**两字段必须成对清空**，facet 项无 `id` 时禁止写 `tagId`）。**壳对页面未监听的 emit（漏接 `change`/`retry-tags`）在 dev 环境 `console.warn`**，防筛选静默失效。**URL 只写白名单字段**：按 scope 用 `Pick<NoteQuery, ...>` 序列化（`pinned` 仅 mine；`archived` 仅 mine/all；`dateRange` 相关仅非 archived），隐藏项一律不写、切 scope 时清理——避免"字段存在性随 scope 漂移"的脏 query 写进 URL。

### 7.5 授权页交互与状态机按钮矩阵

- **Tab 口径**：**登录用户 3 个 Tab**——"我发起的"(`tab=created`，`created_by=me`) / "我授权的"(`tab=granted`，`grantor_id=me` 全状态；含"待我确认"职责) / "涉及我的"(`tab=incoming`，`grantee_id=me AND created_by<>me`)；**ADMIN 额外第 4 个"全部授权"**(`tab=all`)。非 ADMIN 只看前 3 个，ADMIN 看 4 个（`NoteUserGrantView` 按 `isAdmin` 分支渲染）；**非 ADMIN 手改 `?tab=all` → 前端忽略该参数回退 `created` 并 toast"该视图仅管理员可用"**（后端 403 仍为最终防线，页面不因此落入通用错误态）。
- **Tab 查询**：后端 `GET /note-grants?tab=` 一个端点覆盖四 Tab（不再有独立 `/pending`、`/all`，消解双入口）。**唯一过滤条件见 后端文档 §5.2 Tab 过滤表**：`created=created_by=me`；`granted=grantor_id=me`（全状态）；`incoming=grantee_id=me AND created_by<>me`（仅 incoming 需排除 S 发起人，created 绝不加）。**SUPERIOR 行（口径以后端文档 §5.2 为准：`grantor`=日志所有者=被选中的下属 G，`grantee`=当前用户（上级 A），`created_by`=A）**：A 在"我发起的"(created) 出现（`created_by==me`，可撤回自己的 PENDING）；G 在"我授权的"(granted) 出现（`grantor==me`），**可确认/拒绝/撤回**，**批准后变 APPROVED 仍在该 Tab 可撤销/升级**（grantor 始终有入口）；G 的"涉及我的"不重复（`created_by==me` 已排除）。**视角速记**：A（上级）在 `created` 只看到"我请求查看下属日志"、只能撤回；G（下属）在 `granted` 才能确认/拒绝——A 在 `granted` 看不到该行是设计使然，不是漏行。**payload 只带 `grantorId`（=G）+ `role`，`granteeId` 由服务端推导为 me、误传即 400/50015**——这既是 `NoteGrantForm` 的 `SuperiorGrantPayload`，也是 `BbUserPicker scope='subordinate'` 的依据。**与 `managerCanReadSubordinate` 的边界**：后端 SUPERIOR 授权本身不受开关约束，但 `BbUserPicker scope='subordinate'` 的数据源（`GET /users?scope=subordinate`）在开关关闭时返回空数组 → **开关关闭时 SUPERIOR 表单实际选不到人**；前端在 `managerCanReadSubordinate !== true` 时直接把 SUPERIOR 表单置为禁用并提示「下属功能未开启，暂无法发起上级授权」（本期接受该限制，不做手填 userId 兜底）。行内 `direction` 仅展示（可能为 `none`），列加"发起人"显示 `createdBy`，二者并存不混。
- **用户选择器**：`BbUserPicker` 授权场景传 **`multiple=false`（单选）**；`mode=SUPERIOR` 传 **`scope='subordinate'`**（数据源限下属）或由组件二次过滤，仍保留服务端校验"仅能选择下属"提示（避免选到非下属提交后才 400/403）。
- **按钮矩阵（按"当前所在 Tab/身份"渲染，`can*` 后端计算前端只读）**：
  | 状态       | 我发起的(created)                                                                  | 我授权的(granted)                                                             | 涉及我的(incoming) | ADMIN 全部(all) |
  | -------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------- | -------------- | ------------- |
  | PENDING  | 撤回（`created_by==me`）                                                           | **确认 / 拒绝 / 撤回**（grantor==me；\** 允许 grantor 确认前撤回，与"发起人可撤回自己的 PENDING"一致） | —              | 代撤销（PENDING）  |
  | APPROVED | 升级/撤销（grantor==me 时）；**`isAdmin && created_by==me` 可撤销（不可升级，除非 grantor）**；否则只读 | **撤销 / 升级**（grantor==me）；admin 代授权行 grantor A 亦可撤销                        | —              | 代撤销（APPROVED） |
  | REJECTED | 只读                                                                             | 只读                                                                        | 只读             | 只读            |
  | REVOKED  | 只读                                                                             | 只读（grantor 可看历史）                                                          | 只读             | 只读            |
- **`can*` 判定伪代码**（后端口径，前端只读不重算；供联调对表）：
  ```ts
  canApprove = status==='PENDING'  && grantorId===me
  canReject  = canApprove
  canUpgrade = status==='APPROVED' && grantorId===me
  canRevoke  = status==='PENDING'  ? (grantorId===me || createdBy===me || isAdmin)
             : status==='APPROVED' ? (grantorId===me || isAdmin)
             : false
  ```
  （`createdBy===me` 覆盖"我发起的 PENDING 可撤回"；`isAdmin` 覆盖"ADMIN 代撤销"；APPROVED 的 created 行仅 `isAdmin && createdBy===me` 可撤销、不可升级，故不入 `canUpgrade`。）**与按钮矩阵的对齐说明**：矩阵按 Tab 渲染（created Tab 只展示 `createdBy==me` 的行），`canRevoke` 是全局判定，二者不冲突——前端**一律按后端下发的 `can*` 渲染，不自行叠加 Tab 条件**。
- **确认文案**：撤销 PENDING → "确认撤销该授权？将停止该用户查看权限"；撤销 APPROVED → "撤销后将立即收回该用户当前及未来日志的查看/编辑权限（含历史）"；均为二次确认对话框。
- **403 语义统一 helper**：`isScopeDisabled403(err, scope)`（=`err.status===403 && (scope==='subordinate' || scope==='all')`）——`subordinate`→"下属日志功能未开启，请联系管理员"，`all`→"仅管理员可查看"；两者都渲染 `errorMode='empty'`、不显示重试、不 toast。新增 scope 只改该 helper 一行，避免 403 文案漏判。
- **ADMIN 代撤销**：ADMIN 在"全部"对 **PENDING/APPROVED 任意行**可代撤销（`canRevoke=true`；REJECTED/REVOKED 已无"撤销"语义，只读）；在"我发起的"(created) 对**本人发起行**（`created_by==me`）——`grantor==me` 可升级/撤销，`isAdmin && created_by==me`（ADMIN 代授权行）可撤销、不可升级（除非 grantor），其余只读；其余 Tab 只读。

### 7.6 引用选择器细节与 backlinks 展示

- `NoteRelationPicker` 入参：`sourceNoteId`（**选择器排除当前 note，防自引用**）、`existingTargets: Array<{targetType,targetId}>`（**已引用项置灰 + "已引用"角标**）、`defaultMode:'NOTE'|'TASK'`（**初始 Tab**）。**组件内部持 NOTE/TASK 两个 Tab（与 后端文档 §5.5 一致），`mode` 完全为内部状态（`defaultMode` 仅作初始 Tab；`mode` 为内部状态，不做受控 `v-model:mode`）**；`existingTargets` 随当前 Tab 按 `targetType` 过滤（NOTE Tab 只对 NOTE 已引用置灰，TASK Tab 只对 TASK 置灰）。**切换 note 时重置 Tab**：父组件用 `:key="sourceNoteId"` 重建 picker（内部 `mode` 随之回到 `defaultMode`），组件内部不再额外 `watch`。
- **已引用数据来源**：`existingTargets` 由详情页 `relations` 传入（每次搜索不同步返回 `alreadyLinked`），保证与详情一致。
- **搜索结果过滤 archived**：note 目标搜索（scope=visible）返回前过滤 archived；task 目标搜索（`/tasks/search`）后端已按 isVisible 过滤。**别把两件事混为一谈**：①"过滤 archived"＝前端对 note 搜索结果做的结果过滤；②"`scope=visible` 开关关闭静默省略下属分支"＝后端可见性聚合（返回 200，不 403）。
- **backlinks（谁引用了我）**：详情页独立区块"来源日志"，展示 `NoteBacklinkVO` 的 `sourceSummary（来源摘要）+ sourceOwnerName（来源作者）+ createdByName（引用人，可空显示"—"）+ createdAt（引用时间）`（来源作者 ≠ 引用人，EDITOR/ADMIN 给他人 note 加引用时引用人为 EDITOR/ADMIN），点击跳 `/notes/{sourceNoteId}` 进入来源详情（不可见来源已整条过滤，不占位）；空态"暂无日志引用这篇日志"。

### 7.7 附件上传体验

- **多文件**：支持多选（`multiple`），逐个上传**并发上限 3**，每个文件独立 `AbortController`；已有 `BbAttachmentList` 单文件 input 升级为多文件。
- **上传 API 签名**：统一封装支持进度与取消——
  ```ts
  interface UploadOptions { onProgress?: (percent: number) => void; signal?: AbortSignal }
  uploadFile(file: File, opts?: UploadOptions): Promise<FileVO>            // note/通用（taskId=null）
  uploadTaskFile(taskId: number, file: File, opts?: UploadOptions): Promise<FileVO>
  ```
  `onProgress` 映射 axios `onUploadProgress`，`signal` 传 axios `signal`；**取消后移除临时进度项、清理半截对象**；`NoteAttachmentList` 暴露 `uploadingList`/`cancel(uploadId)`/`retry(uploadId)`（§7.10 契约同步）。`uploadId` 由前端在 `upload(file)` 时生成（`crypto.randomUUID()`），上传成功后映射到 `attachmentId`；`cancel/retry` 用 `uploadId` 定位上传队列项（上传中/失败时无 `attachmentId`）；`remove` 仍用 `attachmentId`（仅对已落库附件）。`uploadingList` 结构：`Array<{uploadId:string, file:File, progress:number, status:'queued'\|'uploading'\|'binding'\|'done'\|'failed'，attachmentId?:number}>`。`api/file.ts` 不再返回裸 `Promise<FileVO>` 而无进度/取消入口。**渲染合并规则**：先按顺序渲染 `items`（已落库），再把 `uploadingList` 中 `status!=='done'` 的项追加在其后作为临时行（`queued`/`uploading`/`binding`/`failed` 各带进度或重试按钮）；`done` 项在父组件替换 `items` 后从 `uploadingList` 移除，**同一附件在列表里只会出现一次**。
- **限制（单位/空语义）**：`maxSize/allowedExt` **从后端配置下发**。**OpenAPI 明确单位与空语义，避免前端歧义**：`maxSize: number`（**字节**，如 `52428800`，前端换算为可读字符串；不用 `"50MB"` 字符串、不用 `50`(MB) 二义值）；**前端 fallback 与后端同源**：`DEFAULT_MAX_SIZE = 50 * 1024 * 1024` 只在 `api/file.ts` 定义一处，`/files/config` 失败或未返回时用它，禁止在组件里写字面量、`allowedExt: string[]`（**空数组 `[]` 明确表示"不限制类型"**，禁止被 `Array.every`/`includes` 误判为"拒绝所有"；非空则白名单，如 `['jpg','png']` 无点号；**前端比对先去点再小写**：`file.name.split('.').pop()!.toLowerCase()`）。后端 `application.yml` 默认 `STORAGE_MAX_SIZE:50MB`、`allowed-ext` 留空不限类型；前端仅按下发值做**前置拦截与提示**（对应后端 `40002/40003`），无法下发时按后端默认展示。
- **三套下载 URL 由后端下发、前端只透传**：note `/notes/{id}/attachments/{aid}/download`、task `/tasks/{tid}/attachments/{aid}/download`、通用 `/files/{id}`（仅创建者/ADMIN）；`fetchAttachment(url)` **不拼路径、不区分来源**，只做相对路径安全校验。**本期不提供通用 `/files` 删除入口**（note 走"移除关联"、task 走 task 端点），该端点仅供后端/未来文件管理页。
- **附件复用范围**：后端支持"同一附件被多个 note 引用"（`UNIQUE(note_id, attachment_id)` 只保证不重复绑定），但**本期 UI 不提供"从已上传文件选关联"入口**——二次关联只能经 API 完成；新增 note 附件一律走"上传 → 绑定"，避免为此引入文件管理页与配额语义。
- **进度与失败**：上传中显示进度条，可单个取消；失败可重试，"附件已上传但关联失败"提示（不静默）；未保存态附件区禁用 + "保存后可添加附件"。
- **缩略图（生命周期）**：图片经 note 专用下载端点 blob 转 objectURL，**统一走 `attachmentBlobCache`（key=`attachmentId+size`），不各组件建 Map**——同一附件在多卡片/详情出现时只下载一次；`onBeforeUnmount` 统一 `revokeObjectURL`；列表滚动用虚拟滚动按可见项懒加载；`contentType` 为空或非图片（image/*）时**回退文件图标、不创建 objectURL**。列表显示上传者、上传时间。**不引入拖拽上传**（本期范围外）。

### 7.9 文案与状态统一清单

- **枚举中文文案**（`utils/i18n` 或常量）：visibility `PRIVATE=私密/INTERNAL=本部门/PUBLIC=公开`；grantRole `VIEWER=可查看/EDITOR=可编辑/OWNER=所有者/ADMIN=管理员`；status `PENDING=待确认/APPROVED=已生效/REJECTED=已拒绝/REVOKED=已撤销`；mode `OWNER=主动授权/SUPERIOR=上级授权/ADMIN=管理员授权`；**`direction` 展示**：`none` → "—"（仅展示、不参与任何按钮判断），其余值按后端枚举映射中文。
- **错误态统一（按业务码分支，不依赖 HTTP status（scope=subordinate 例外））**：后端业务异常一律 HTTP 200 + `ApiResult`，故**页面捕获 `code` 而不是 `error.status`**——**但 `scope=subordinate` 开关关闭是 HTTP 级 403（不返回 `ApiResult`），不走业务码链路**，前端须在此特例下捕获 `err.status===403`。`errorCode.ts` 增加常量：`NOTE_NOT_FOUND(50001)` → **NotFound 空态**"日志不存在或无权访问"；`NOTE_SCOPE_DISABLED(50016)` → **仅作后端日志/审计用，前端不按此 code 分支**（前端改为捕获 `err.status===403 && route.meta.scope==='subordinate'` 渲染空态"下属日志功能未开启，请联系管理员"，不 toast，见 §4）；`NOTE_DEPT_REQUIRED(50017)` → 保存时提示"当前账号无部门，无法设为本部门可见"；其余 5xxxx → 按表映射（文案统一"工作日志"）。`fetchAttachment`/详情/列表统一经 `http.ts` 拦截器把 code 映射到 `BizError` 后按此分支（HTTP 403/400 等 HTTP 协议级错误不经 `BizError`，由 `http` 拦截器直接抛 `HttpError`，页面按 `err.status` 分支）。
- **`VERSION_CONFLICT(10006)`（三动作）** → 弹"内容已被他人更新"对话框，明确三个动作：
  1. **查看最新**：只读打开服务端最新版本，**当前编辑器草稿原样保留**（不覆盖、不丢失）；
  2. **以最新为基准重新编辑**：**二次确认**"当前未保存内容将被替换"后再用最新内容载入编辑区；
  3. **保留我的草稿**：把本地草稿**（`NoteDraft`：noteId + content + logDate + visibility + tagIds + version + updatedAt）存入页面级 `draft` 状态**，并在编辑器提供"恢复草稿"入口（经 `NoteEditor.draft` 初值回灌，见 §7.10）——**不只保留正文，冲突前改的日期/可见性/标签一并保留**。剪贴板复制仅作辅助：`navigator.clipboard` 在非 HTTPS/非用户手势下会失败，**不得作为唯一通道**；**失败降级**：改为弹出只读文本框（内容已全选）+「手动复制」提示，不静默失败。

**`NoteQuery` / `NoteQueryForm` / `NoteQueryPatch`**—— 冻结单一事实源方案：

- **`NoteQuery`（传输层类型，由 OpenAPI 生成）**：`pnpm gen:types` 后存在于 `api.d.ts`，对应后端 `NoteQueryDTO`，包含全部查询字段（`scope/keyword/tagId/tagName/visibility/pinned/archived/start/end/date/sort/page/size`，与 NoteQueryForm/NoteQueryPatch 同源）。**前端不再手写 `interface NoteQuery`**。`useNoteList.query: ComputedRef<NoteQuery>` 返回的就是该生成类型。
- **`NoteQueryForm`（UI 层窄化类型，前端手写）**：筛选条 UI 使用的类型，**只含 UI 可编辑字段**，不含 `scope`（由 route.meta 注入）、`page`/`size`（由分页单一入口管理）。定义：

```ts
// frontend/src/types/note.ts
import type { NoteQuery } from '@/types/api';  // 项目生成类型统一在 @/types/api
import type { NoteScope, NoteVisibility } from '@/types/api';

// UI 层窄化：不含 scope/page/size（这三个由 route.meta / 分页入口管理）
// tag 字段拆分为 tagId/tagName——OpenAPI 单个 query 参数只能生成 string，
//   无法表达 number|string 联合；mine 传 tagId(number)、其余 scope 传 tagName(string)，
//   前端按 scope 决定写哪个字段，后端 DTO 同时接收 tagId/tagName 并按 scope 优先级解析。
export type NoteQueryForm = Omit<NoteQuery, 'scope' | 'page' | 'size' | 'tag'> & {
  tagId?: number;    // mine scope 用：选中标签的 id
  tagName?: string;  // 其余 scope 用：选中标签的 name
};

// 筛选条 change 事件 patch：只含本次变更字段，不含 scope/page/size
export type NoteQueryPatch = Omit<Partial<NoteQuery>, 'scope' | 'page' | 'size' | 'tag'> & {
  tagId?: number;
  tagName?: string;
};
```

- **`tag` 字段冗余说明**：OpenAPI 生成的 `NoteQuery` 仍保留 `tag`（后端 `NoteQueryDTO` 遗留字段），前端已 `Omit`、不发不收；**清理后端 DTO 是独立小项、不阻塞前端**，清理前禁止任何组件读 `NoteQuery.tag`。
- **`NoteFilterBar.query: NoteQueryForm`**（UI 层用 `NoteQueryForm`，非 `NoteQuery`）；**`NoteFilterBar.change: [patch: NoteQueryPatch]`**；**`NoteListView.query: NoteQueryForm`**；**`NoteListView.change: [patch: NoteQueryPatch]`**（与 `NoteFilterBar.change` 一致；`change` 是 NoteListView 的第 9 个 emit，纳入事件清单与单测）。
- **传值方式**：页面传 `list.query.value`（解包 `ComputedRef<NoteQuery>`，赋值给 `query: NoteQueryForm` 时 TS 结构兼容——`NoteQuery` 是 `NoteQueryForm` 的超集，可直接赋值，但**必须经 `toNoteQueryForm(q)` 显式剥离 `scope/page/size`**——否则 `NoteFilterBar` 会从 query 读到分页字段、渲染出不该存在的隐藏控件；该映射函数与 `NoteQueryForm` 同文件导出并单测覆盖）。`useNoteList.setQuery(patch: NoteQueryPatch)` 内部合并到 `queryByScope[scope]`、重置 page=1、写 URL、发请求。

**`NoteQuery` 字段口径**——后端 `NoteQueryDTO` 字段（OpenAPI 生成 `NoteQuery`）：

- `scope?: NoteScope`——由 route.meta 注入，不写入 URL query
- `keyword?: string`
- `tagId?: number`——mine scope 传选中标签的 id（OpenAPI 单参数只能 string，拆为 `tagId`/`tagName`）
- `tagName?: string`——其余 scope 传选中标签的 name
- `visibility?: NoteVisibility`
- `pinned?: boolean`
- `archived?: boolean`——仅 mine 与 ADMIN scope=all 生效；其余 scope 后端忽略
- `start?: string` / `end?: string` / `date?: string`——YYYY-MM-DD；`date` 与 `start/end` 互斥
- `sort?: 'log_date_desc' | 'log_date_asc' | 'created_desc' | 'updated_desc'`
- `page?: number`——1-based
- `size?: number`——默认 PAGE_SIZE=20；右栏 isolated 实例传 5

**`NoteCalendarScope`**——`type NoteCalendarScope = Exclude<NoteScope, 'visible'>`，日历 scope 选择器类型（mine/shared/explore/internal/subordinate/all，6 个，不含 visible）；`useMonthCalendar.scope`、`NoteCalendarView` scope 选择器、`setScope` 入参全程使用该类型；`visible` 无独立日历落地页（仅用于引用选择器搜索与列表查询值）。

**筛选条渲染归属**：`NoteListView` **内部渲染**共享 **`NoteFilterBar`**（壳用 `filterConfig` 配置显隐 + `query` 传入当前值 + `@change` 透传 patch 到页面 `list.setQuery`）——`NoteFilterBar` 是筛选控件的唯一实现，**7 页不再在 `#filters` 插槽中重复实例化**（无 `#filters` 插槽）；与 `NoteListView.filterConfig`（显隐配置）+ `useNoteList.setQuery`（写入契约）三者闭合。各 scope 页的 `NoteFilterConfig` 默认显隐需逐项写死（7 个 scope 的默认配置表：mine 全 true、shared/explore/internal/subordinate 隐藏 pinned、all 隐藏 pinned + 仅 ADMIN 可见、archived 隐藏 dateRange）；**只有 `undefined` 字段才回落 `true`**，每个 scope 按上文默认表写死、不依赖缺省。日期模式从"某天"切到"范围"时，`NoteFilterBar` 发出 `{date: undefined, start: undefined, end: undefined}` 清理旧字段（`setQuery` 支持 `undefined` 删除字段）。`config.search=false` 时不渲染搜索框，`useNoteList` 初始化时忽略/清空 URL 中的 keyword。

## 9. 接口验收矩阵

> 本矩阵由前后端共同执行：前端负责 mock/e2e 侧断言，后端负责接口实现与单测侧断言；端点契约见《Note 模块后端开发方案》§5。

**格式**：`方法 + 路径 + 角色/前置 fixture + 请求 + 期望 HTTP 状态 + 期望业务码 + 期望响应关键字段 + 测试类型（单测/e2e）`。每行分配固定 fixture（用户 u_owner/u_editor/u_viewer/u_admin/u_dept/u_sub/u_public/u_auditor + 部门/授权/note/attachment/relation）。

**HTTP 状态 / 业务码分列说明**：后端业务异常与认证失败均 `ApiResult.fail(...)` 且 HttpStatus 恒为 `200`（由全局异常处理器统一映射），但 **HTTP 协议级错误**（401 未认证 / 403 权限拒绝 / 400 参数格式 / 404 路由不存在 / 405 方法不允许）走标准 HTTP 状态码、**不进入业务码**。故矩阵将"期望 HTTP 状态"与"期望业务码"分列：

- **期望 HTTP 状态**：`200`（业务成功或业务失败包在 `ApiResult.fail`）/ `400`（参数格式/路由参数）/ `401`（未登录，跳登录）/ `403`（权限拒绝，非业务码）/ `404`（路由不存在或 404 语义化）/ `409`（冲突）。
- **期望业务码**：仅 HTTP=200 时有意义，`0`=业务成功，`50001/50006/50007/50008/50013/50014/50017/50020/10002/10006` 为业务失败断言目标。

断言目标错误码汇总：50001（NOTE_NOT_FOUND）/ 50002（NOTE_CONTENT_TOO_LONG）/ 50003（NOTE_TAG_INVALID）/ 50006（NOTE_RELATION_TARGET_NOT_FOUND）/ 50007（NOTE_GRANT_DUPLICATE）/ 50008（NOTE_GRANT_SELF）/ 50012（NOTE_LOG_DATE_INVALID，未来超 7 天）/ 50013（NOTE_FIELD_FORBIDDEN）/ 50014（NOTE_GRANT_FLOW_FORBIDDEN）/ 50017（NOTE_DEPT_REQUIRED）/ 50020（TASK_ATTACHMENT_NOT_LINKED）/ 10002（未登录）/ 10006（VERSION_CONFLICT）。1c=50002、1d-2=50012、1e=50003 已补精确码；50018 不再出现（同一附件允许多 note 引用）。**仅作内部语义、不在矩阵断言**：50015（NOTE_GRANT_MODE_INVALID，HTTP 400）/ 50016（NOTE_SCOPE_DISABLED，HTTP 403；前端捕获 `err.status===403` 而非 code，见 §4/§7.9）/ 50018（NOTE_ATTACHMENT_CANNOT_BIND，HTTP 403，权限层）/ 50019（NOTE_ATTACHMENT_BOUND，task 场景）/ 50021（TASK_ATTACHMENT_FORBIDDEN，HTTP 400）/ 50004（NOTE_ATTACHMENT_INVALID，内部校验）/ 50005（NOTE_ATTACHMENT_NOT_LINKED，内部校验）/ 50009（NOTE_GRANT_NOT_FOUND，404 语义）/ 50010（NOTE_GRANT_NOT_PENDING，归入 50014 流程）/ 50011（NOTE_GRANT_NOT_SUBORDINATE，HTTP 403）。
