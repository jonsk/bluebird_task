## 2. PIPL（个人信息保护法）对照（重点：主管读下属任务）

| 义务 | 状态 | 措施 / 落点 |
|---|---|---|
| 合法性基础（告知-同意 / 人力资源管理所必需） | 🟡 | **组织级只读可见性受 `app.security.manager-can-read-subordinate` 开关控制，默认关**（ADR-012 修订/`02 §4.4`）；启用须**明示告知**员工并记录依据（本表 §2 备注） |
| 最小必要 / 目的限制 | ✅ | 主管仅**只读**可见「下属为 owner 或参与人」的任务；**不扩写权限**（`02 §4.7`）；不含评论/活动流（非目标） |
| 个人权利响应（查询/复制/删除） | 🟡 | 任务 CRUD 支持本人数据管理（`02 §4`）；**导出个人数据** ⛔ 二期 |
| 安全措施（加密/去标识/审计） | 🟡 | 传输 HTTPS 🟡；审计记录访问 ✅（**敏感读审计 `action=read_subordinate`**，`02 §6.3`，0306/Q3）；存储加密 ⛔ 二期 |
| 访问留痕 | ✅ | 主管读取下属任务记入 `audit_operate_log`；审计员可查（`02 §6.5`） |
| 数据留存最小化 | ✅ | 审计保留期默认 ≥180 天，可配（`app.audit.retention-days`，`02 §6.7`） |

> **备注（合规启用前置条件）**：开启 `manager-can-read-subordinate` 前，部署方须完成：① 内部制度/告知文本（员工知晓范围与目的）；② 明确「仅只读、仅下属、仅工作相关任务」；③ 敏感读审计开启并定期审阅。上述为本设计对外声明的**处理依据**，具体法律意见由部署组织法务确认（见 ADR-012 修订）。

## 3. 本期已闭环 vs 列二期 vs 运维待处置

- ✅ **本期闭环**：登录防暴破、安全响应头、乐观锁、职责分离（AUDITOR/USER_MANAGER）、CC 只读、审计缓冲双写+关键同步、审计保留期、调度日志+告警、契约一致性 CI、本对照表。
- ⛔ **列二期**：密码复杂度/过期、双因素、附件病毒扫描、存储加密、强制 HTTPS-only（应用侧）、可观测性（Metrics/Tracing）、实时协同、审计防篡改（hash/WORM）、个人数据导出、多实例 leader 选举。
- 🚫 **已决定不处理（接受风险，2026-09-29）**：S2（企微 `corpSecret` 明文接口）轮换/下线、S5（密钥/`dump.rdb` 入旧 git 历史）清理、PG 备份与恢复演练、HTTPS 证书与网关强制、Redis 持久化安全（`01 §12.1`）。
