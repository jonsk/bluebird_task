# BlueBird 重构 · 合规对照表（含实际差距标注与部署方责任 · 等保 2.0 三级 / PIPL）

> 目的：针对企业级审核（`0306审核_蓝鸟重构方案-企业级审核.md`，Q7）输出**合规对照**，把「标准条款 → 设计措施 → 状态 → 落点」落地为单一对照表。
> 状态图例：✅ 已覆盖（本期设计）｜🟡 部分/受限（有措施但需运维配合或非全面）｜⛔ 列二期（本期不做）｜🚫 已决定不处理（接受风险）｜🛑 运维待处置。

> **定位说明（重要，0306/#2）**：本表为「**对照 + 差距披露**」，**不构成「已达标等保 2.0 三级」的声明**。经产品/运维决策（2026-09-29），多项三级控制**本期不做或接受风险**（见 §3），**实际安全 posture 低于等保三级**；是否满足客户合规要求由**部署方**结合其制度与法律意见自行判定。本表 + §4「部署方责任与风险接受」为书面依据。

## 1. 等保 2.0 三级（安全技术/管理）对照

| 控制域 | 关键条款（摘要） | 状态 | 设计措施 / 落点 |
|---|---|---|---|
| 身份鉴别 | 双因素、口令复杂度与定期更换、登录失败处理 | 🟡 | 登录失败处理 ✅（失败计数+锁定，`02 §2.3/§2.7`，码 `20006`）；口令复杂度/过期、双因素 ⛔ 二期（`01 §3`） |
| 访问控制 | 最小权限、职责分离、默认拒绝 | ✅ | 写权限收敛 `owner/assignee/ADMIN`（CC 只读，`02 §4.7`，0306/Q2）；`AUDITOR`/`USER_MANAGER` 职责分离（`02 §2.4`，ADR-003 修订）；`@PreAuthorize` 默认拒绝 |
| 安全审计 | 审计范围、记录、保护、备份 | 🟡 | 操作/登录日志 `02 §6.2`；关键事件**同步落库**+缓冲双写 `02 §6.7`；保留期 ≥180 天、只追加 ✅；防篡改（hash/WORM）⛔ 二期 |
| 入侵防范 | 最小服务、漏洞、恶意代码 | 🟡 | 生产关 swagger（`02 §1.7`）；未映射 API 统一 404（`02 §1.5`）；附件类型白名单 `02 §5.2`；**病毒扫描 ⛔ 二期** |
| 数据完整性 | 传输/存储完整性与保密性 | 🟡 | 并发乐观锁保完整性（ADR-013）；传输强制 HTTPS 🟡（部署侧/网关）；**存储加密 ⛔ 二期** |
| 数据备份恢复 | 本地/异地备份 | 🟡 | **制品内不做（接受风险）**；**须由部署方落实最低备份**（见 §4）：`pg_dump` 定时导出 + 异机/离线留存 + 定期恢复演练，覆盖业务库与附件目录 `/data/bluebird/files/`。**注：审计 ≥180 天与业务数据同库，无备份则一并丢失——此为审计留存的前置条件**（部署手册 `docs/deployments/` M0 补入；仓内 `scripts/backup.sh` 为样例） |
| 安全通信 | 密码技术、会话、安全标记 | 🟡 | JWT HS256 强 secret ≥256bit（`01 §12`）；refresh 白名单 `02 §2.1`；**安全响应头**（HSTS/CSP 等，`02 §2.7`，0306/Q5）；HTTPS-only 强制 🚫 网关侧不处理（接受风险） |
| 安全运维 | 账密管理、日志、漏洞、配置 | 🟡 | 密钥外置 `./application.yml` chmod600（ADR-010）；CI gitleaks（`01 §11.5`）；**S2/S5 已决定不处理**（`01 §12.1` 🚫） |

## 2. PIPL（个人信息保护法）对照（重点：主管读下属任务）

| 义务 | 状态 | 措施 / 落点 |
|---|---|---|
| 合法性基础（告知-同意 / 人力资源管理所必需） | 🟡 | **组织级只读可见性受 `app.security.manager-can-read-subordinate` 开关控制，默认关**（ADR-012 修订/`02 §4.4`）；启用须**明示告知**员工并记录依据（本表 §2 备注） |
| 最小必要 / 目的限制 | ✅ | 主管仅**只读**可见「下属为 owner 或参与人」的任务；**不扩写权限**（`02 §4.7`）；不含评论/活动流（非目标） |
| 个人权利响应（查询/复制/删除） | 🟡 | 任务 CRUD 支持本人数据管理（`02 §4`）；**导出个人数据** ⛔ 二期 |
| 安全措施（加密/去标识/审计） | 🟡 | 传输 HTTPS 🟡；审计记录访问 ✅（**敏感读审计 `action=read_subordinate`**，`02 §6.3`，0306/Q3）；存储加密 ⛔ 二期 |
| 访问留痕 | ✅ | 主管读取下属任务记入 `audit_operate_log`；审计员可查（`02 §6.5`） |
| 数据留存最小化 | ✅ | 审计保留期默认 ≥180 天，可配（`app.audit.retention-days`，`02 §6.7`） |

> **备注（合规启用前置条件）**：开启 `manager-can-read-subordinate` 前，部署方须完成：① 内部制度/告知文本（员工知晓范围与目的）；② 明确「仅只读、仅下属、仅工作相关任务」；③ 敏感读审计开启并定期审阅。上述为本设计对外声明的**处理依据**，具体法律意见由部署组织法务确认（见 ADR-012 修订）。

## 3. 本期已闭环 vs 列二期 vs 运维待处置

- ✅ **本期闭环**：登录防暴破、安全响应头、乐观锁、职责分离（AUDITOR/USER_MANAGER）、CC 只读、审计缓冲双写+关键同步、审计保留期、调度日志+告警、契约一致性 CI、本对照表。
- ⛔ **列二期**：密码复杂度/过期、双因素、附件病毒扫描、存储加密、强制 HTTPS-only（应用侧）、可观测性（Metrics/Tracing）、实时协同、审计防篡改（hash/WORM）、个人数据导出、多实例 leader 选举。
- 🚫 **已决定不处理（接受风险，2026-09-29）**：S2（企微 `corpSecret` 明文接口）轮换/下线、S5（密钥/`dump.rdb` 入旧 git 历史）清理、HTTPS 证书与网关强制（应用侧）、Redis 持久化安全（`01 §12.1`）。
- ⚠️ **制品内不做、转部署方责任（见 §4）**：**PG 备份与恢复演练**（审计留存前置条件）、HTTPS-only 强制、存储加密、病毒扫描、审计防篡改。

## 4. 部署方责任与风险接受（量化差距，0306/#2 · #4）

> 本系统以「单机轻量交付」为目标；下列等保三级/相关控制**本期未在制品内实现**，经决策「接受风险」（2026-09-29）。**部署方**须书面确认并在其运维体系中补齐，否则**不得对外声明合规达标**：

| 控制项 | 制品现状 | 部署方须落实（最低） |
|---|---|---|
| 数据备份恢复 | 不做 | `pg_dump` 定时（建议每日）导出 + 异机/离线留存 + **定期恢复演练**；覆盖业务库与附件目录 `/data/bluebird/files/` |
| 传输强制 HTTPS-only | 不做 | 前置网关/负载均衡强制 TLS、关闭明文 HTTP；证书生命周期管理 |
| 口令复杂度/过期 | ⛔ 二期 | 客户强制时二期实现，或由统一身份 OIDC 承担 |
| 存储加密 | ⛔ 二期 | 依赖磁盘/卷加密（LUKS/TDE 等）部署侧手段 |
| 附件病毒扫描 | ⛔ 二期 | 网关接入杀毒网关，或书面接受风险 |
| 审计防篡改（hash/WORM） | ⛔ 二期 | 日志外发 SIEM / WORM 存储 / 异地归档 |
| 组织级只读可见性（PIPL） | 默认关 | 开启前完成**告知文本 + 法务确认**（见 §2 备注） |

> 上述事项的**风险接受/补齐**由部署组织签署确认；本设计仅提供「差距披露 + 最低指引」，具体法律意见由部署组织法务确认。
