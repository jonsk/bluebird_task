# BlueBird 任务管理系统 · 重构详细方案（Engineering Spec）

> 决策基线（已确认）：
> - **Monorepo 单仓库 + 整体重写 + 新建 Git 仓库**

## 1. 背景与目标

### 1.1 现状
旧系统为前后端分离：后端 `bluebird_task_End`（Spring Boot 3.2 + MySQL + Redis + 企业微信），前端 `bluebird_task_Front`（若依 RuoYi-Vue 脚手架二次开发的 Vue3 任务管理）。核心能力：任务 / 子任务 / 标签 / 分类 / 自定义栏 / 收藏，按「我的一天 / 未来7天 / 我@Ta / 分配给我 / 收藏 / 全部」展示，企业微信扫码登录 + 通讯录同步。

> 修订 B8（旧前端六大视图基线，已实测核实；ADR-007 限定：**仅作视图语义参考，不代表数据继承；新系统六大视图为全新实现**）：旧前端**确实定义了六大视图**，作为「路由 + 数据接口」两级基线存在——
> - 路由：`/index`(myDay)、`/myWeek`、`/myJoin`、`/myDo`、`/myCollect`、`/allTask`（`src/router/index.js` + `src/utils/utils.js` 的 `TASK_TYPE_*` 常量）。
> - 数据接口：`src/api/todoList/record.js` 提供 `getMyDay` / `getMyWeek` / `getMyJoin` / `getMyDo` / `getMyCollect` / `getAllTask` 一一对应。
> - UI 实现：仅 `index.vue`（复用于多数视图，按 `route.name` 切换）+ `list1.vue`（全部任务），**非各自独立页面组件**。
>
> **因此「视图一致」的有效基线 = 上述路由路径与接口语义**，与后端设计 `02 §4.4` 的 `scope`(day/week/joined/assigned/collect/all) 一一对应。新前端建议各视图仍可复用统一组件，但以 `scope` 参数驱动，接口语义与旧版保持一致。

### 1.2 目标
1. **安全**：彻底解决密钥入库泄漏问题；统一鉴权。
2. **可维护**：模块化、分层规范、Flyway 版本化、统一错误码/响应体、完整测试。
3. **可复现**：Docker / 手动 jar 两种部署方式，一键起环境。
4. **数据干净**：收敛重复模型（`task_record`/`task_record_subtable`、3 套组织表 + 2 套用户表并存，多为死表）。
5. **前端清爽**：去除若依遗留，重写为 TS + 组件化。

### 1.3 成功标准
- 外部身份源登录（按部署所选 provider）+ 账号密码均可用，权限正确。
- 六大任务视图数据正确，接口语义与设计一致（assigned=ASSIGNEE、joined=CC、collect=收藏等）。
- 一条命令起完整环境；手动 jar 部署也有完整文档。
- 仓库无明文密钥，`gitleaks` 通过。
- 核心接口有自动化测试，CI 全绿。

## 3. 范围与非目标

**范围内**
- 任务管理核心（任务/子任务/标签/分类/自定义栏/收藏/日历）
- OIDC 统一外部认证（配置式接入任意 OIDC IDP；企微例外）+ 账号密码登录 + 组织同步（SCIM/PULL/PUSH/NONE 四模式，ADR-008）
- 附件上传/下载/预览
- 操作日志、登录日志
- 全新部署链路

**明确不做（本版本）**
- 多租户 / 多企业
- 移动端 / 小程序 / H5
- K8s（仅 Docker Compose 或 jar）
- 微服务 / 分布式事务
- 即时通讯 / 审批流 / 消息中心（如需，后续迭代）

### 4.2 模块划分与职责
| 模块 | 职责 | 关键类 |
|---|---|---|

| `config` | Security、MyBatis、Flyway、OpenAPI、Web/CORS、Jackson、异步 | `SecurityConfig`、`MybatisPlusConfig`、`OpenApiConfig` |

### 4.3 依赖规则（强制，CI 用依赖检查）
```
audit  ← 所有模块（通过事件/注解）
task   → identity, org, file
file   → (可独立)
identity, org → (独立)
禁止：模块间反向依赖、跨模块直接 import internal 包
```

## 7. 后端详细设计

### 7.1 分层规范（以 task 为例）
```
controller/       仅参数绑定 + 校验注解 + 调 application，无业务逻辑
application/      @Service 用例编排、@Transactional 边界、集成调用
domain/           实体 + 领域规则（POJO，不依赖框架/MyBatis）
infrastructure/   MyBatis mapper/repository 实现
dto/              CreateCmd / UpdateCmd / Query / VO
```

**Controller 示例**
```java
@RestController
@RequestMapping("/api/v1/tasks")
@RequiredArgsConstructor
@Tag(name = "任务")
public class TaskController {
    private final TaskApplicationService taskApp;

    @GetMapping
    public ApiResult<PageResult<TaskVO>> page(@Valid TaskQuery query) {
        return ApiResult.ok(taskApp.page(query));
    }

    @PostMapping
    @PreAuthorize("hasAuthority('task:create')")
    public ApiResult<Long> create(@Valid @RequestBody TaskCreateCmd cmd) {
        return ApiResult.ok(taskApp.create(cmd));
    }

    @PostMapping("/{id}/complete")
    public ApiResult<Void> complete(@PathVariable Long id) {
        taskApp.complete(id);
        return ApiResult.ok();
    }
}
```

**Application 示例**
```java
@Service
@RequiredArgsConstructor
public class TaskApplicationService {
    private final TaskRepository taskRepo;
    private final TaskParticipantRepository partRepo;

    @Transactional
    public Long create(TaskCreateCmd cmd) {
        Long me = SecurityUtils.currentUserId();
        Task task = Task.create(cmd, me);
        taskRepo.save(task);
        partRepo.saveAll(task.getId(), cmd.getAssigneeIds(), cmd.getCcIds());
        return task.getId();
    }
}
```

**Domain 示例**
```java
public class Task {
    private Long id; private Long parentId;
    private String title; private String content;
    private TaskStatus status; private boolean completed;
    private Instant dueAt; private Instant remindAt;
    private JsonNode cycleRule; private Long categoryId;
    private Long ownerId; private Integer priority;

    public static Task create(TaskCreateCmd cmd, Long ownerId) {
        Task t = new Task();
        t.title = cmd.getTitle(); t.ownerId = ownerId;
        t.status = TaskStatus.ACTIVE; t.completed = false;
        return t;
    }
    public void complete() {
        if (this.completed) throw new BusinessException(ErrorCode.TASK_ALREADY_COMPLETED);
        this.completed = true;
    }
}
```

### 7.2 统一响应体
```java
public record ApiResult<T>(int code, String message, T data, String traceId) {
    public static <T> ApiResult<T> ok()          { return ok(null); }
    public static <T> ApiResult<T> ok(T data)    { return new ApiResult<>(0, "ok", data, TraceContext.get()); }
    public static <T> ApiResult<T> fail(ErrorCode ec) { return new ApiResult<>(ec.getCode(), ec.getMsg(), null, TraceContext.get()); }
}
```
前端统一解包：`{ code === 0 }` 为成功。

> 修订 C4（成功码切换策略）：新系统成功码统一为 **0**（旧 `ResponseResult` 为 200/500）。因旧系统直接停用、新系统重新部署（ADR-007），不存在新旧并行/双跑期，无需兼容旧 200 成功码。

### 7.6 认证设计

**架构**（ADR-008）：`app.identity.provider` 三态 `LOCAL|OIDC|WECHAT`，**部署时选定不可变**：
- `LOCAL`（**默认**）：仅本地账号密码登录，不装配任何外部源（`external/config` 返回 `provider=LOCAL`，前端不渲染外部登录入口）。**默认私有化部署只走本地账密**，最简。
- `OIDC`（可选）：认证层统一走 OIDC（Spring Security OAuth2 Client 配置式），覆盖 Google/Keycloak/Casdoor/竹云/Azure/Okta/钉钉/飞书等任意 OIDC IDP。
- `WECHAT`（可选）：企业微信因 OIDC 支持不完整保留 `WechatIdentityAdapter` 作为例外。

**账号密码登录**（始终可用，与外部源无关；`provider=LOCAL` 时即唯一登录方式）
```
POST /api/v1/auth/login {username,password}
 → MyUserDetailsService 校验 → 签发 access+refresh → 写登录日志（含 IP/UA）
```

**OIDC 外部认证**（provider=OIDC，仅启用时；Spring Security OAuth2 Client，**过滤器全页跳转**）
```
前端:  GET /api/v1/auth/external/config → {provider:"OIDC"}（前端仅据此渲染外部登录按钮，不自管授权地址）
       点击「OIDC 登录」→ 前端整页跳转【Spring 授权发起端点】/oauth2/authorization/oidc（修订 R9）
发起:  Spring Security OAuth2 Login 生成并管理 state/nonce（服务端持有，防 CSRF/重放），302 → IDP 登录页（Google/Keycloak/Casdoor/竹云等）
跳转:  IDP 认证后 302 重定向回回调地址（浏览器整页，非 XHR)
回调:  GET /api/v1/auth/external/callback（由 OAuth2LoginAuthenticationFilter 拦截，校验 state/nonce，code→id_token）
后端:  1. Spring Security 交换 code→id_token → 解析 sub（= externalId）+ name/email
       2. 查 sys_user(external_id=sub, deleted=0)
          - 有：校验 status → 签发 token
          - 无且 auto-create-user=true：自动建号（role_code=COMMON, dept_id=NULL, must_change_password=0）→ 签发 token
          - 无且 auto-create-user=false：拒绝（NO_PERMISSION_EXTERNAL）
       3. 写登录日志
       4. successHandler 302 重定向到前端 https://<app>/oauth/success#access_token=..&refresh_token=..
          （失败带 error；用 **hash fragment 而非 query**——fragment 不随请求发服务器、不进浏览器历史/Referer/访问日志；前端读后立即 history.replaceState('#') 清除，修订 RF2）
```

**企业微信认证**（provider=WECHAT，仅启用时；例外保留单独 Adapter，独立 Controller 回调）
```
前端:  GET /api/v1/auth/external/config  → {provider:"WECHAT", corpId, agentId}
       前端渲染企微扫码组件 → 扫码后获得授权 code（前端 XHR 直调后端，企微无需服务端会话状态）
回调:  GET /api/v1/auth/wechat/callback?code=xxx（独立路径，Controller + WechatIdentityAdapter）
后端:  1. WechatIdentityAdapter.loginByCode(code) → userid（= externalId）
       2. 查 sys_user(external_id=userid, deleted=0)，无则拒绝（企微不自动建号，须先同步或 ADMIN 手建）
       3. 签发 token，返回 TokenVO 给前端
```

> OIDC 与企微的区别：OIDC 用户可自动建号（首次登录即创建），企微用户不自动建号（须先由组织同步或 ADMIN 手建）。原因：OIDC IDP 通常是企业统一身份管理入口，用户已存在；企微场景需先同步组织确定归属。
> 修订 M1（独立审核收敛，取代原 F6）：**OIDC 与企微回调地址拆分**——OIDC=`/api/v1/auth/external/callback`（Spring Security OAuth2 过滤器，**整页 302 跳转**，非 XHR）；企微=`/api/v1/auth/wechat/callback`（独立 `Controller` + `WechatIdentityAdapter`，前端 XHR 直调）。二者**不再共用一个 URL**，消除企微 code 被 OAuth2 过滤器误当 OIDC 处理的冲突。OIDC 需显式 `SecurityFilterChain.oauth2Login().redirectionEndpoint().baseUri("/api/v1/auth/external/callback")` 重绑定过滤器仲裁（仅改 `registration.oidc.redirect-uri` 不会让默认 `OAuth2LoginAuthenticationFilter` 拦截新路径）；成功后 `AuthenticationSuccessHandler` 签发 app token，**302 重定向到 SPA `https://<app>/oauth/success#access_token=..&refresh_token=..`**（**hash fragment 传 token，修订 RF2**——避免 query 落浏览器历史/Referer/服务器日志；前端读后 `history.replaceState('#')` 清除），前端 `OidcSuccessView` 读取写入 store，**不再 XHR 直调回调**。

**Token**
- `access`：短效（默认 3600s），`Authorization: Bearer`
- `refresh`：长效（7 天），`POST /api/v1/auth/refresh` 换取
- 无状态（STATELESS），Redis 存 refresh token 白名单用于登出失效

**白名单**（免鉴权，与 02 §1.7 逐条统一）：`/api/v1/auth/**`、`/api/v1/bootstrap/admin`（仅无 ADMIN 时可用，正常返回 403，见 §8.2.1）、`/api/v1/scim/v2/**`（SCIM 标准端点）、`/api/v1/org/push`（私有 IDM 推送端点）、`/actuator/health`。`/v3/api-docs/**`、`/swagger-ui/**` **仅 dev 放行**（`DOC_ENABLED=true` 时，见 §7.5）；生产 `DOC_ENABLED=false`，二者从白名单移除、springdoc 关闭，防接口信息暴露。
> 修订 F2/F3（十三审）：`/api/v1/scim/v2/**` 与 `/api/v1/org/push` 免 **JWT** 鉴权，但**必须由独立 `SecurityFilterChain` 校验 Bearer `ORGSYNC_PUSH_TOKEN`**（`app.orgsync.push-token`）。若仅列入白名单而不挂独立链，二者将无鉴权；若不列入白名单，`JwtAuthenticationFilter` 会因缺 JWT 拦截，导致 SCIM/PUSH 同步实测不可用（见 §7.7）。两文档白名单须逐条对齐。
> 修订 B2：**`/api/v1/files/**` 不入白名单**。附件下载/预览必须登录，并在 `FileController` 内校验任务归属/权限（见 §7.8 / §12 第 7 条）。
> 修订 G2（十四审）：移除白名单尾部「kkfileview 预览代理如启用则单列」注记——预览已统一为需登录的 `GET /api/v1/files/{id}/preview`（后端按 id 鉴权后代理，见 F9 修订），**不存在需单独放行的 kkfileview 路由**；kkfileview 若独立部署，仅容器内网可达、不对外暴露，故无需进入免鉴权白名单。
> 修订（ADR-009，单制品）：内嵌前端的静态资源需放行——追加 `/`、`/index.html`、`/favicon.ico`、`/assets/**` 免鉴权（**不含 `/api/v1/**`**），并配 SPA history 回退；详见 §11.4。

### 7.7 定时任务与组织同步

**组织同步四模式**（ADR-008，由 `app.orgsync.mode` 配置）：
- `SCIM`：暴露 `/api/v1/scim/v2/*` 标准端点（Users/Groups），被动接收 SCIM 2.0 兼容 IDP（Keycloak/Casdoor/Okta/Entra ID）推送。Bearer token 鉴权（`ORGSYNC_PUSH_TOKEN`）。零代码。
- `PULL`：`OrgSyncService` 每天 01:00 调用 `OrgSyncAdapter.syncOrg()`（企微/钉钉/飞书），主动拉取并增量 upsert `sys_department`/`sys_user`。Redis 分布式锁保证单实例幂等。
- `PUSH`：暴露 `POST /api/v1/org/push` 接收端点，适配竹云等私有 IDM 推送。`OrgPushAdapter` 解析私有 JSON 格式并 upsert。Bearer token 鉴权。
- `NONE`（**默认**）：不同步。用户由 ADMIN 手工创建；若启用 OIDC 也可由首次登录自动建号（`dept_id=NULL`），ADMIN 手动分配部门。

**任务提醒**：`TaskRemindService`（可选一期）：扫描接近 `remind_at` 的任务，推送应用消息（企微/钉钉/飞书）或邮件（OIDC IDP 无应用消息通道时）。

#### 8.2.1 首 ADMIN 初始化（R25，ADR-007 补充）
> 问题：空库起步后无任何用户，`POST /api/v1/users`（建用户）鉴权=ADMIN，形成死锁。须有首 ADMIN 引导机制。

**机制（两分支，互为兜底）**：

1. **应用启动种子（主分支）**：`CommandLineRunner`（或 Flyway **Java 迁移** `V2__SeedAdmin`）在启动时检测 `sys_user` 无 `role_code=ADMIN` 且 `deleted=0` 的记录，若**且** `BOOTSTRAP_ADMIN_PASSWORD` 环境变量非空，则用 `BCryptPasswordEncoder` 计算 `BOOTSTRAP_ADMIN_PASSWORD` 的哈希，插入初始 ADMIN：
   - `username` = `${BOOTSTRAP_ADMIN_USERNAME:admin}`，`role_code=ADMIN`，`status=ACTIVE`
   - `password` = BCrypt 哈希（**由应用层在 Java 代码中计算，不在 SQL 中做哈希**——Flyway SQL 迁移无法执行 BCrypt，`${...}` 占位符仅做字面文本替换，不计算哈希）
   - `external_id` = NULL（本地账号，不绑外部源）
   - `must_change_password` = 1（首次登录强制改密）
   - **触发条件**：仅当「无 ADMIN」**且** `BOOTSTRAP_ADMIN_PASSWORD` 非空时执行；变量为空则跳过本分支，交由启动探测兜底。**ADR-010 自动生成后 `BOOTSTRAP_ADMIN_PASSWORD` 默认非空，主分支自动执行**；兜底分支仅当释放配置被删 / 手动清空该变量时才触发。

2. **启动探测（兜底分支）**：应用启动时检测 `sys_user` 无 `role_code=ADMIN` 且 `deleted=0` 的记录（且种子分支未执行，如 `BOOTSTRAP_ADMIN_PASSWORD` 未设置），则开放一次性引导接口 `POST /api/v1/bootstrap/admin`（免鉴权，仅此场景），由部署人员手动调用创建首个 ADMIN，创建后该接口自动关闭。

> 职责澄清：种子分支依赖环境变量自动完成（无人值守部署首选）；探测分支为人工兜底（环境变量未设置或需交互式引导时使用）。两分支均以「无 ADMIN」为前置条件，不会重复建号。**常态下 ADR-010 自动生成 `BOOTSTRAP_ADMIN_PASSWORD` 非空，种子主分支自动执行，兜底分支近乎不触发**；仅当释放出的配置文件被删 / 手动清空该变量时才走人工引导，实现者无需每次都调 `bootstrap/admin`。

**安全要求**：
- `BOOTSTRAP_ADMIN_PASSWORD` 由首次运行 `ConfigFileReleaser` **自动生成强口令**（控制台/受保护日志打印一次，详见 §11.7/ADR-010），**如需自定义可用环境变量覆盖**；首次登录后强制改密（`sys_user.must_change_password` 标记，登录后重置为 0）。
- 引导接口仅在「无 ADMIN」时可用，正常状态返回 403。
- 种子/引导均不提交明文密码到仓库；BCrypt 哈希由应用层运行时计算。

**环境变量**（见 §15.1；**默认自动生成，可选覆盖**，勿填弱占位值）：
```
BOOTSTRAP_ADMIN_USERNAME=admin          # 可选覆盖首 ADMIN 用户名（默认 admin）
BOOTSTRAP_ADMIN_PASSWORD=               # 默认自动生成强口令；如需自定义在此覆盖
```

### 8.3 数据模型设计决策清单（修订 B5，已确认）
> 以下为相对旧模型的**设计取舍**决策（非迁移损耗，ADR-007 不迁移旧数据）。以下决策**已经评审确认**，记录于 `04决策记录(ADR).md`；实现按此执行，不再视为未定项。

| # | 设计决策 | 影响 | 已确认决策 |
|---|---|---|---|
| 1 | 任务分类为单一 `task.category_id`（非多对多） | 每任务仅一个分类 | **已确认**：每任务一个主分类，多分类需求用标签满足 |
| 2 | `status`(ACTIVE/DISABLED/ARCHIVED) + `completed` 两列表达任务状态 | 状态语义清晰 | `status` 管理生命周期，`completed` 独立标记完成。**`ARCHIVED` 为旧库不存在的新增语义**（旧 `task_status` 仅 0启用/1禁用 + `complete_status` 0未完成/1已完成），经产品确认保留归档能力；`cycle_rule` JSONB(`{freq,interval,byDay}`) 亦为全新格式（**完整字段 `{freq,interval,dtstart,byDay,count,until,tz}` + 计算式展开见 `02 §4.3`**），旧 `task_cycle varchar` 无对应基线（ADR-007 不迁移，实现需自测覆盖） |
| 3 | `task` 无 `sort` 列 | 不支持手动排序 | **已确认：本版不支持手动排序**，仅按 `02 §4.4` 规则排序；`sort` 列列入二期（P2）需求 |
| 4 | `sys_user.dept_id` + `sys_user_department`（多部门，`is_primary` 标记主部门） | 支持多部门 | `dept_id` 冗余主部门并与 `sys_user_department` 保持一致。**合并旧 `sys_user`(本地账号) + `user`(外部用户，`varchar user_id`/mobile/email/avatar/position) 为单一 `sys_user`**，以 `external_id` 承载外部标识（OIDC sub/企微 userid），`password` 对外部用户可空 |
| 5 | `task` 自关联 `parent_id`（主/子任务同表） | 支持多级 | 保留两级约定（前端 UI），新模型理论上支持多级，不额外限制 |
| 6 | RBAC 简化为 `sys_user.role_code` 单列（ADMIN/COMMON） | 无多角色与按钮级权限 | **已确认（N1）**：无 `sys_role`/`sys_auth` 等表，按 `role_code` 区分；按钮级权限本期不做，`sys_permission` 不建（如后续需要再补） |

> 以上默认口径为**建议值**，最终以产品确认与 ADR 记录为准。

## 11. DevOps 与部署

### 11.0 部署形态（ADR-009：单制品）
**唯一制品 `bluebird-task.jar`，内嵌前端，不使用 Nginx。** 前端 `dist` 在打包期注入 jar 的 `static/`，由内嵌 Tomcat 统一提供页面与 `/api/v1` 接口，对外只需一个端口。

### 11.1 Docker Compose（`deploy/docker-compose.yml`）
```yaml
services:
  postgres:
    image: postgres:16
    restart: unless-stopped
    environment:
      POSTGRES_DB: bluebird
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck: { test: ["CMD","pg_isready","-U","${DB_USER}"], interval: 5s }
  redis:
    image: redis:7
    restart: unless-stopped
    command: ["redis-server","--requirepass","${REDIS_PASSWORD}"]
    volumes: ["redisdata:/data"]
  backend:                       # 唯一应用制品：jar 内含前端（ADR-009）
    build:
      context: ..                # 构建上下文=仓根（需访问 frontend/）
      dockerfile: backend/Dockerfile
    restart: unless-stopped
    env_file: ../.env
    environment:
      DB_URL: jdbc:postgresql://postgres:5432/bluebird
      REDIS_HOST: redis
    ports: ["8080:8080"]         # 单端口对外，无 Nginx
    volumes: ["${STORAGE_PATH}:/data/bluebird/files"]
    depends_on: [postgres, redis]
volumes: { pgdata: {}, redisdata: {} }
```
> 已移除独立 `frontend` 与 `nginx` 服务（ADR-009）。

### 11.2 Backend Dockerfile（多阶段：前端构建 → 内嵌 → 后端打包）
```dockerfile
# 1) 构建前端
FROM node:20-alpine AS front
WORKDIR /build/frontend
COPY frontend/package.json frontend/pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY frontend/ ./
RUN pnpm run build                       # → /build/frontend/dist

# 2) 构建后端（把 dist 作为静态资源打进 jar）
FROM maven:3.9-eclipse-temurin-21 AS back
WORKDIR /build
COPY backend/pom.xml ./
COPY backend/src ./src
COPY --from=front /build/frontend/dist ./src/main/resources/static
RUN mvn -B -DskipTests package           # → target/bluebird-*.jar（含前端）

# 3) 运行
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=back /build/target/bluebird-*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java","-jar","app.jar"]
```
> 构建上下文为**仓根**：`docker build -f backend/Dockerfile -t bluebird .`。

### 11.3 前端构建与内嵌（不再单独出镜像）
- 本地/CI：`pnpm -C frontend install --frozen-lockfile && pnpm -C frontend build` → `frontend/dist`。
- Maven 打包（容器外常规路径）：`backend/pom.xml` 用 `maven-resources-plugin` 把 `${project.basedir}/../frontend/dist` 拷贝到 `${project.build.outputDirectory}/static`（绑定 `prepare-package`）；若需"一条命令出 jar"，可改用 `frontend-maven-plugin` 在 `generate-resources` 阶段执行 pnpm 构建。
- `frontend/dist`、`backend/src/main/resources/static/` 均为构建产物，**不入 git**。
- **CI 顺序（修订 G6/R6 叠加）**：单制品 pipeline 必须**固定顺序**——①前端 `pnpm build`（产物路径约定：`frontend/dist`）→ ②把 `dist` 内容拷贝至 `backend/src/main/resources/static/`（`maven-resources-plugin` 绑定 `prepare-package`，源 `${project.basedir}/../frontend/dist`）→ ③`mvn verify` 打 jar；任一前置失败即中止，禁止「后端独立出 jar 不含前端」。制品 `bluebird-task.jar` **带前端版本哈希**标识（构建号），**回滚 = 替换上一个 jar + 保留 `./application.yml`**（ADR-010），CWD=jar 目录；CI 产物需校验 jar 内含 `static/index.html` **与至少一个 `static/assets/` 条目**（`jar tf` 断言）——既防 dist 未注入、也防 assets 目录空导致白屏（修订 R1）。

### 11.4 静态资源与 SPA 回退（由后端提供）
- **Security 放行**（在 §7.6 白名单基础上追加静态资源，**不含 `/api/v1/**`**）：`/`、`/index.html`、`/favicon.ico`、`/assets/**`。
- **资源映射（修订 R1）**：`spring.web.resources.add-mappings: false` 仅关闭 Spring Boot 的**默认**静态映射（用于让未映射 API 走 `NoHandlerFoundException`）；静态资源必须由 `WebConfig.addResourceHandlers` **显式注册** `/assets/**`、`/`、`/index.html`、`/favicon.ico`（否则 `/assets/*.js|css`、`/favicon.ico` 因 Accept 不含 text/html 既不服务也不回退 → **404 白屏**）。`/assets/**` 长缓存 `immutable` 与 `/index.html` no-cache 在此配置（详见 `02 §1.7.1`）。
- **history 路由回退**：`Vue Router` 采用 history 模式，刷新子路由需回退到 `index.html`。新增 `SpaForwardController`（或 `ErrorViewResolver`）：请求**非** `/api/v1/**`、`/actuator/**`、`/v3/api-docs/**`、`/swagger-ui/**`，**非**静态资源，且 `Accept` 含 `text/html` 时转发 `/index.html`；**API 的 404 仍返回 JSON `ApiResult`，不得被回退吞掉**。
- **API 404 机制（修订 RF6）**：未映射 `/api/v1/**` 经 `spring.mvc.throw-exception-if-no-handler-found` + `web.resources.add-mappings=false` 抛 `NoHandlerFoundException` → `GlobalExceptionHandler` 统一转 `ApiResult{code:10004}`（详见 `02 §1.5/§1.7.1`）；不交给 Spring 默认 HTML 404。
- **缓存**：`/assets/**`（Vite 文件名含 content hash）设 `Cache-Control: public, max-age=31536000, immutable`；`/index.html` 设 `no-cache`，保证发版即时生效。
- **压缩**：内嵌 Tomcat 开 `server.compression.enabled=true`（替代原 Nginx gzip）。

### 11.7 运行时配置释放（config extraction，ADR-010）
- **默认内置**：jar 内打包一份默认配置 `classpath:/application.yml`（**不含真实密钥**，仅占位符 / 本地开发默认值）。
- **首次运行释放**：应用启动时检测运行目录（= jar 所在目录 / `java -jar` 的工作目录）是否存在 `application.yml`；**不存在则**把内置默认复制为 `./application.yml`；**已存在则不覆盖**（保留用户修改）。实现沿用旧系统已验证的 `BlueBirdApplication.checkAndCopyConfig()` 范式。
- **后续读取**：Spring Boot 默认配置优先级 `file:./application.yml` > `classpath:/application.yml`；用户修改外部文件后**重启即生效，无需重打包**。
- **升级**：新 jar 替换旧 jar 后，运行目录已有的 `application.yml` **不被覆盖**，用户配置持久保留。
- **敏感值**：内置默认文件**不含任何真实密钥**。释放后按「能自生成的才首次生成、必须与外部一致的只留占位」分类（ADR-010）：
  - **首次自动生成并预填**：`JWT_SECRET`（随机 32B）、`BOOTSTRAP_ADMIN_PASSWORD`（生成强口令 + 控制台/保护日志打印一次 + 首登强制改密）。自生成项**允许环境变量覆盖**（部署方显式指定则用之，见 §15.1）。
  - **外部注入（只留 `${...}` 占位）**：`DB_URL/USER/PASSWORD`、`REDIS_PASSWORD`、`OIDC_CLIENT_ID/SECRET`、`WECHAT_CORP_SECRET`、`ORGSYNC_PUSH_TOKEN`——须与外部系统匹配，由用户填写或 `EnvironmentFile`/Compose 注入（§12 第 4 条）。
  - 生成的密钥仅写运行目录配置文件（`chmod 600`），不入仓库、不入内置默认。
  - **空值覆盖保护**：自生成密钥**不在 `.env` 留空占位**——`.env` 经 `EnvironmentFile`/`env_file` 注入的 OS 环境变量优先级高于 `file:./application.yml`，留空串会**覆盖自动生成值**，使首 ADMIN 回落人工引导；`.env` 仅承载外部注入类，需自定义自生成密钥时填**非空**值（详见 `§15.1` / ADR-010 §5）。
- **日志 / 存储目录**：配置文件同时承载 `logging.file.name`（日志目录，如 `/srv/bluebird/logs/bluebird.log`）与 `app.storage.root`（文件存储目录，如 `/srv/bluebird/files`），首次释放即有可用默认值，用户可按需改。
- **配置丢失自愈**：删除配置文件后下次启动自动重新释放并重生成 `JWT_SECRET` → 已签发 refresh 失效，用户需重新登录（可控）。
- **运行约定**：`cd <jar 目录> && java -jar bluebird-task.jar`，保证释放与读取同一目录。

| 需求范围蔓延（加消息/审批） | 中 | 明确本版不做，用 ADR 记录待办 |
| 前端从若依脚手架重写工作量大 | 中 | 只保留业务视图，遗留全删，TS 化 |
| 缺少测试骨干技能 | 中 | 教师模板 + 关键路径优先覆盖 |

## 15. 附录：环境变量与启动手册

### 15.1 环境变量清单（`.env`）
> **注意（部署优先级）**：自动生成的密钥（`JWT_SECRET`、`BOOTSTRAP_ADMIN_PASSWORD`）由首次运行写入**释放出的 `./application.yml`**（`chmod 600`），**不在 `.env` 留空占位**——若经 systemd `EnvironmentFile` / Compose `env_file` 注入 OS 环境变量，Spring 优先级为「OS 环境变量 > `file:./application.yml`」，空字符串会**覆盖自动生成结果**，导致首次 ADMIN 回落人工引导。`.env` 只承载**外部注入类**（`DB_*`/`REDIS_*`/`OIDC_*`/`WECHAT_*`/`ORGSYNC_*`/`IDENTITY_PROVIDER`）；仅当确需自定义密钥时才在 `.env` 填**非空**值。
```
# DB
DB_URL=jdbc:postgresql://localhost:5432/bluebird
DB_USER=bluebird
DB_PASSWORD=CHANGE_ME
# Redis
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=CHANGE_ME
# JWT（默认自动生成、写入 application.yml；切勿留空占位——空值会覆盖自动生成结果。仅在确需自定义时填非空值）
JWT_SECRET=                            # 默认首次运行自动生成随机 32B 写入 application.yml（ADR-010）；需自定义时在此填非空值（勿留弱值）
JWT_ACCESS_TTL=3600
JWT_REFRESH_TTL=604800
# 首 ADMIN 初始化（R25，ADR-007；默认自动生成，可选覆盖；同上，勿留空占位）
BOOTSTRAP_ADMIN_USERNAME=admin         # 可选覆盖首 ADMIN 用户名（默认 admin）
BOOTSTRAP_ADMIN_PASSWORD=              # 默认自动生成强口令写入 application.yml；需自定义时填非空值
# 外部认证（ADR-006/ADR-008；默认 LOCAL=仅本地账号密码，OIDC/WECHAT 为可选）
IDENTITY_PROVIDER=LOCAL            # LOCAL|OIDC|WECHAT
AUTO_CREATE_USER=true             # OIDC 用户首次登录是否自动建号（LOCAL/WECHAT 不适用）
# OIDC（provider=OIDC 时填写，适配任意 OIDC IDP；默认关闭）
OIDC_ISSUER=                      # 如 https://keycloak.example.com/realms/myrealm
OIDC_CLIENT_ID=
OIDC_CLIENT_SECRET=
# 企业微信（provider=WECHAT 时填写，ADR-008 例外；默认关闭）
WECHAT_CORP_ID=
WECHAT_CORP_SECRET=
WECHAT_AGENT_ID=
# 组织同步（ADR-008，与认证独立配置）
ORGSYNC_MODE=NONE                 # SCIM|PULL|PUSH|NONE
ORGSYNC_ADAPTER=                  # PULL: WECHAT|DINGTALK|FEISHU；PUSH: ZHCLOUD 等
ORGSYNC_PUSH_TOKEN=CHANGE_ME      # SCIM/PUSH 模式：推送端鉴权 token
# 附件存储
STORAGE_PATH=/data/bluebird/files
STORAGE_URL_PREFIX=/api/v1/files
# 接口文档（springdoc）：生产关闭防暴露，dev 联调设 true
DOC_ENABLED=false                  # 生产 false；dev true 暴露 /v3/api-docs 与 /swagger-ui
# 前端
VITE_API_BASE_URL=/api
```

### 15.2 启动手册
```bash
# 容器方式（推荐）
cd deploy
cp ../.env.example ../.env   # 填入真实值（勿提交）
docker compose up -d --build   # 仅 pg + redis + backend（单制品，ADR-009）

# 手动 jar 方式（单制品，无 Nginx）
# 1. 起 PG + Redis（或已有）
# 2. 构建前端
cd frontend && pnpm install && pnpm run build      # → frontend/dist
# 3. 构建后端（打包期把 dist 内嵌进 jar）并运行
cd ../backend && mvn -B package                    # → target/bluebird-task.jar（含前端）
java -jar target/bluebird-task.jar                 # 默认 :8080，页面与 /api/v1 同源
```
