### 1.2 目标
1. **保留业务行为**：六大视图、任务全生命周期、子任务、标签/分类/自定义栏/收藏/日历、人员分配、附件预览、登录（OIDC/企微/账密）——行为与旧系统等价或按新设计明确改进。
2. **去脚手架**：移除若依 `system/monitor/tool` 遗留与 Jeecg 残留，形成干净的前端工程。
3. **类型安全 + 契约驱动**：TS strict + `openapi-typescript` 生成接口类型，杜绝 `any` 与手工拼字段。
4. **可维护**：消灭 984 行级巨型组件，组件原子化、状态 Store 化、业务分层。
5. **可回归**：以自动化手段（视觉回归 + E2E）替代「靠人眼对照」，使重写效果**可度量、可验收**。

### 1.3 范围与非目标
- **范围**：Web 端（桌面优先），任务管理、组织/用户管理、附件、审计日志、登录。
- **非目标**：移动端/小程序/H5（01 §3）；多租户；K8s；即时通讯/审批流。

## 2. 重写质量保障策略（核心）

> **本节回答：「前端有大量手写组件，如何保证重写效果？」**
> 核心结论：**不能靠「重写后肉眼对比」保证质量**。必须把「旧手写组件的隐形行为」显式化为**可执行的基线**，再用**设计系统 + 契约 + 自动化回归**三重手段收敛。落地为「三步法」：**① 基线冻结 → ② 设计系统重构 → ③ 对照验收**。

### 2.1 为什么手写组件是重写最大风险
1. **行为隐形**：手写组件里大量业务规则以「代码细节」存在，无注释无文档。例：`TaskCard.vue` 的逾期着色规则 `diffDays<=0 → 红、<5 → 绿`、标签含「紧急」红/「重要」蓝，全靠读源码才能知道。
2. **耦合隐式**：旧组件通过 `inject("indexPageObj")`、全局 `proxy.$modal`、`getCurrentInstance()`、巨型 Store 隐式耦合，行为散落。
3. **边界多**：完成态/失败回滚、子任务联动、收藏切换、权限（仅 owner 可完成/加子任务）等边界条件多，漏一个即「看起来对、用起来错」。
4. **无契约**：旧接口无 OpenAPI、无 TS 类型，字段靠约定，重写易错位。
5. **不可并行验证**：ADR-007 决定旧系统停用、不迁移数据，**无法新老双跑对照真实数据**——更要靠人工基线 + Mock 数据集。

### 2.2 三步法总览

```
① 基线冻结 (Baseline Freeze)
   旧源码 → 逐组件导出《行为契约》+《黄金截图集》+《E2E 场景清单》
   （在旧前端仍可运行期间完成，产出物纳入仓根 docs/frontend-baseline/，见 §3.2）

② 设计系统重构 (Design System First)
   Design Tokens → BB 原子组件 → 业务组件 → 页面
   用统一组件替代 90% 手写重复；消灭巨型组件

③ 对照验收 (Golden Acceptance)
   视觉回归（Playwright 截图 diff）+ E2E（业务场景）+ 单测（逻辑）
   DoD 卡点：三项全绿才允许合并
```

### 2.3 ① 基线冻结

#### 2.3.1 行为契约导出（每个手写组件一份）
对 §1.1 清单中每个组件，产出 `docs/frontend-baseline/contracts/<Component>.md`，模板如下：

```markdown
# 行为契约：<旧组件名> → <新组件名>
- 用途：
- 输入/状态来源：props / inject / store / 全局
- 展示规则：（含着色、格式化、条件显示）
- 交互清单：<动作> → <效果> → <接口> → <异常/回滚>
- 业务规则：（阈值、权限、去重等硬规则）
- 边界与已知缺陷：（旧实现 bug，重写是否修正）
- 验收用例：（可直接转为 E2E 步骤）
```

**示例（已从源码导出）——`TaskCard.vue` → `BbTaskCard`（文件 `BbTaskCard.vue`）：**
| 项 | 契约内容 |
|---|---|
| 用途 | 列表中的单个任务项 |
| 状态来源 | `props.task`（新类型 `TaskVO`，含 `owner: {id,name}`（映射旧 `belongUserId`）、`assigneeIds`、`ccIds`、`participantIds`）；`inject("indexPageObj")`；`taskStore`/`userStore` |
| 展示规则 | 创建时间「M月D日」；子任务 `completedTotal/total`；日期文本；重复文本；提醒文本；标签；附件图标；`@人员` 列表（均超长省略 + tooltip）；完成态标题加删除线（收藏视图除外） |
| 着色规则 | 日期：`diffDays<=0` → `task-date-overdue`(红)；`diffDays<5` → `task-date-near`(绿)；否则默认。标签：含「紧急」红、含「重要」蓝、否则默认 |
| 交互 | 勾选完成 → `changeIsFinished/changeIncomplete`，**失败回滚 checkbox 状态**；子任务折叠 toggle；标题点击 → 打开右侧详情抽屉；收藏星标切换；「移动任务」弹窗（选自定义栏 → `addTaskByCustom`）；「删除任务」二次确认 → 删除并关闭右栏 |
| 权限 | **参与者可写（修订 RF3，与后端 §4.7 对齐）**：当前用户 ∈ {owner, assignee, cc}（或 ADMIN）时显示「加子任务」入口、可勾选完成/操作；非参与者只读。判定用 `task.owner.id`（映射旧 `belongUserId`）与 `task.participantIds`，不单看 owner |
| 边界/缺陷 | `onMounted` 用 `document.querySelector('.tast-item')` 量宽（脆弱，重写改用 CSS/ResizeObserver）；`changeBtnFlag` 防抖 |
| 验收用例 | 1) 完成失败后勾选自动回滚；2) 逾期日期显示红色；3) 非参与者不显示加子任务/可否决完成；4) 子任务折叠可切换 |

> 该导出**必须基于旧源码**，且在旧前端可运行期间补齐「录屏/截图」证据，避免仅靠推断。

#### 2.3.2 黄金截图集（Golden Screenshots）
- 工具：Playwright，在旧前端以 **固定 Mock 数据**渲染各页面/组件，按固定视口（如 1440×900）截图，纳入 `docs/frontend-baseline/screenshots/` 版本化。
- **旧前端 Mock 注入方式（修订 M3）**：旧前端 `utils/request.js`（axios）走**真实旧后端 API**，不对接「固定 Mock」；须用 Playwright `page.route('**/api/**', route => route.fulfill({json: fixture}))` 在浏览器层拦截旧接口并返回与该新前端 MSW **同一份** fixture（`docs/frontend-baseline/fixtures/` 的 JSON 序列化跨新旧前端共享、版本化），否则旧/新前后端无法同数据对比。
- 覆盖：六大视图列表、任务卡片（正常/逾期/临期/完成/收藏）、新增任务块、右侧详情抽屉、左栏（视图+分类树+组织树）、标签配置、日历、登录页、人员选择器、各下拉（日期/重复/提醒）。
- 用途：新前端同数据同视口截图 → **像素/结构化对比**（见 §2.5.1）。

#### 2.3.3 E2E 场景清单
把「用户故事」写成脚本（先对旧前端跑通，作为基线；再对新前端跑，作为验收）。至少覆盖：
登录（账密/企微/OIDC 跳转）；六大视图切换与计数；新建任务（含子任务/日期/重复/提醒/人员/标签/附件）；完成任务与失败回滚；收藏/取消；移动任务到自定义栏；删除；分类树增删改；标签增删改；人员选择器按部门筛选；附件上传/预览；用户/部门管理（ADMIN）；审计日志查询（ADMIN）。

### 2.4 ② 设计系统重构
1. **Design Tokens 先行**：颜色/间距/圆角/字号/阴影/语义色（`--bb-color-overdue` 等）集中定义，替换旧散落的 `var(--bg-primary)`、硬编码色值。产出 `styles/tokens.css` + Tailwind 主题映射。
2. **BB 原子组件**：`BbButton/BbInput/BbSelect/BbModal/BbDrawer/BbTag/BbIcon/BbTree/BbTable/BbPagination/BbEmpty/BbTooltip`（多数在 Element Plus 之上薄封装，统一交互与主题）。目标：业务组件中**不再直接散写 Element Plus 细节样式**。
3. **业务组件原子化**：把 §1.1 中巨型/耦合组件拆解为「展示组件 + 容器组件 + Store/composable」：
   - `RightBoxDialog.vue(984)` → `BbTaskDetailDrawer`（容器）+ `BbTaskDetailForm` + `BbSubtaskList` + `BbAttachmentList` + `BbParticipantList` + `useTaskDetail()` composable。
   - `TaskCard.vue` → `BbTaskCard` + `BbTaskMetaLine`（展示规则）+ `useTaskCardActions()`。
   - `LeftBox` → `BbFilterRail`（固定视图）+ `BbCategoryTree` + `BbOrgTree`。
4. **禁止项（评审红线）**：单文件 > 400 行必须拆分；禁止 `inject` 隐式传参（改 props/Provide 显式契约）；禁止在组件内直接 `axios`（统一走 `src/api/*`）；禁止 `any`。

### 2.5 ③ 对照验收
#### 2.5.1 视觉回归
- 新前端用**同一套 Mock 数据**（§2.6）渲染 → Playwright 截图 → 与黄金截图对比。
- 判定（修订 G7）：**结构化 DOM 断言为主判据**（元素位置/文案/颜色/可见性/类名），像素 diff 为辅（≥ 阈值差异告警但不一票否决——跨机/字体渲染易波动）；关键布局/文案/颜色必须一致。**基线更新由前端评审责任人批准**并在 DoD 卡点记录（有意改进 → 更新黄金集 + 留痕）。
- 组件级「视觉单测」：对 `BbTaskCard` 等用 Vitest + `@vue/test-utils` 快照。

#### 2.5.2 E2E 回归
- Playwright 跑 §2.3.3 场景清单，对**契约 Mock 后端**（见 §2.6）执行；断言请求/响应与 UI 状态。
- 关键交互（完成回滚、收藏、移动、删除确认）必须有断言。

#### 2.5.3 逻辑单测
- Vitest 覆盖纯逻辑：日期/逾期着色（`useTaskDateStatus`）、标签颜色、`TASK_TYPE_*` 视图映射、请求层错误码处理、Store actions。
- 目标：核心 composable/util 覆盖率 ≥ 80%（分支）。

### 2.6 契约 Mock（适配「不迁移数据」）
- 由 `docs/api/openapi.yaml` 生成类型；同时用 **MSW（Mock Service Worker）** 按 OpenAPI 生成 Mock 端点（Prism 已去除，ADR-011，避免双方案），提供**固定 fixture 数据集**，覆盖边界：逾期/临期/已完成任务、多子任务、周期任务、多附件、多部门用户、禁用用户、空列表、大分页。
- **仅 dev/test 装载（修订 L6）**：MSW 须仅以 `import.meta.env.DEV` 或测试环境挂载（`NODE_ENV=development|test` 才 `import` 并 `setupWorker().start()`），**生产构建（`pnpm build`/`NODE_ENV=production`）剔除 MSW 依赖与入口**，避免生产包挟持真实请求；CI 产物需验证 `dist/` 不含 `mockServiceWorker.js` 引用。
- fixture 数据与黄金截图使用**同一份**，保证「视觉基线可复现」；审计「周期任务」等边界用例需覆盖（M2 计算式展开的实例展示）。
- **旧系统运留窗口（修订 M3）**：基线冻结依赖旧系统**可运行**。须在隔离环境（staging/sandbox）保留「旧后端 + 种子数据 + 旧前端」供 M0 基线冻结，**与生产「旧系统随新部署停用」并存**——旧系统在**M5 正式销毁前一直保留于隔离区**，避免基线冻结与销毁抢时间窗（ADR-007 的「不迁移数据」针对业务数据，不矛盾）。
- 作用：前端可**脱离后端独立开发与回归**（符合「不迁移旧数据、旧系统停用」的现实）。

### 2.7 类型契约（契约驱动开发）
- CI 步骤：`openapi-typescript docs/api/openapi.yaml -o src/types/api.d.ts`，接口层 `src/api/*` 仅包装生成类型，禁止手写响应类型。
- 若契约变更 → 重新生成 → TS 编译失败即暴露破坏性变更。

### 2.8 代码规范、评审与 DoD
- ESLint + Prettier + `vue-tsc`（TS strict）；提交钩子校验。
- PR 评审清单：契约对齐？拆分达标（<400 行）？无 `any`？无隐式 `inject`？新增 E2E/单测？视觉基线已更新？
- **完成定义（DoD）**：某页面/组件「完成」＝ 单测绿 + E2E 绿 + 视觉对比通过 + 无 TS/console 错误 + 评审通过。四缺一不算完成。
  > 修订 R14（MSW 质量卡点入 DoD）：**`pnpm build` 后 `dist/` 不得含 `mockServiceWorker.js`**（MSW 仅 dev/test 装载，防止 mock 泄漏进生产）；此断言纳入 DoD/CI 门禁（配合 §2.6 的 dist 校验），为搬迁移质量关键卡点，须逐步把关。

## 4. 工程规范

### 4.1 请求层（`api/http.ts`）
- 基址 `VITE_API_BASE_URL`；统一前缀 `/api/v1`。
- 请求拦截：注入 `Authorization: Bearer <access>`；写入 `traceId`。
- 响应拦截：解包 `ApiResult`；`code!=0` → 抛业务错误（携 `code/message/traceId`）；`10002 UNAUTHENTICATED` → 触发刷新或跳登录；`20005 TOKEN_INVALID` → 尝试 `POST /api/v1/auth/refresh` 续签，失败则登出。
- 错误映射：`utils/errorCode.ts` 与后端 `ErrorCode`（02 §1.4）逐一对齐。

### 4.2 状态管理（Pinia）
| store | 职责 |
|---|---|
| `auth` | access/refresh、当前用户摘要、登录/登出/刷新 |
| `permission` | 路由/按钮权限（`role_code` ADMIN/COMMON → 前端能力位） |
| `task` | 列表（按 scope 缓存）、详情、过滤器；**拆分**旧 `task.js` 的编辑/子任务职责到 composable |
| `tag` / `category` / `menu` | 标签 / 分类树 / 自定义栏 |
| `user` | 用户与部门树（人员选择器数据源） |
| `app` | 布局状态（左栏折叠、主题） |

> 规则：Store 只放跨组件共享的**领域状态**；单组件交互状态用 `ref/computed`；副作用（请求）放 Store action 或 composable。

### 4.3 路由与权限
- `routes/` 声明式路由；动态路由按权限注入。
- 元信息：`meta:{ title, requiresAuth, roles:['ADMIN'] }`。
- 守卫：未登录 → 登录页；无权限 → 403。
- 六大视图路由沿用语义化路径：`/index`(day)、`/myWeek`、`/myJoin`、`/myDo`、`/myCollect`、`/allTask`（与旧一致，旧前端基线见 `01 §1.1` 修订 B8 注记）。
- **路由↔scope 映射表（修订 R9-契约）**：路由名与后端 `scope` 参数**非直映射**（`/myDo`≠`assigned`、`/myJoin`≠`joined`），统一在路由 resolve 时经下表注入 `?scope=`，防止接错：

  | 路由 | scope（发给 `GET /tasks?scope=`） | 视图 |
  |---|---|---|
  | `/index` | `day` | 我的一天 |
  | `/myWeek` | `week` | 未来 7 天 |
  | `/myJoin` | `joined` | 我@Ta的（CC） |
  | `/myDo` | `assigned` | 分配给我的（ASSIGNEE） |
  | `/myCollect` | `collect` | 我的收藏 |
  | `/allTask` | `all` | 全部任务 |

  > 路由守卫/utils 只认**路由名**，视图数据统一经映射表取 `scope`；避免在多个组件里散写 `scope` 常量导致路由与请求参数漂移。
- **视图映射留痕（RF-LINK 确认）**：旧 `TASK_TYPE_*` 六常量中 `LINK` 即 `allTask`（全部任务）视图的内部别名，**已由新设计 `all=全部任务` 视图覆盖**；**不新增显式「任务关联」功能、不建 `task_link` 表**（需求确认，用户拍板），实现勿误建。
- 按钮级：`v-permission` 指令按 `role_code` 控制（本版仅 ADMIN/COMMON，无按钮级权限表，见 02 §2.4）。

### 4.4 样式与设计令牌
- `styles/tokens.css` 定义色板与语义色（含 `--bb-color-overdue`/`--bb-color-near`），Tailwind 映射；Element Plus 主题变量覆盖。
- 禁止组件内硬编码主色；业务色值走 token。

### 4.5 通用能力
- `utils/preview.ts`：重写旧 `previewFile`（kkfileview），走新文件接口 `/api/v1/files/{id}/preview`（02 §5.5），不再拼旧 `/sys/file/download`。
- `utils/date.ts`：统一格式化（ISO8601 + `+08:00`），替换旧 `fomatDateFun`。
- 常量：`TASK_SCOPE`（day/week/assigned/joined/collect/all）、`PRIORITY`、`TASK_STATUS`、`PARTICIPANT_ROLE`。

## 5. 模块详细设计

### 5.1 认证模块
- `LoginView`：由 `GET /api/v1/auth/external/config` 决定渲染：`provider=LOCAL`（**默认**）→ 仅「账号密码」表单；`provider=OIDC` → 额外渲染「OIDC 登录」按钮，点击**整页跳转 Spring 授权发起端点 `/oauth2/authorization/oidc`**（由服务端生成/校验 state/nonce 并 302 到 IDP，**前端不自管 OAuth 状态/不直接跳 `authorizationUri`**，修订 R9，与后端 02 §2.3 一致）；`provider=WECHAT` → 额外渲染企微扫码组件；始终提供「账号密码」登录，外部源为可选（ADR-008）。
- `OidcSuccessView`（原 `OidcCallbackView`，M1 收敛）：OIDC 由 Spring Security 过滤器**整页回调**，成功后被 302 重定向回本页 `https://<app>/oauth/success#access_token=..&refresh_token=..`（失败带 `error`）。**token 经 hash fragment 传入**（修订 RF2：防 Query 落浏览器历史/Referer/服务器日志）；本页读取 fragment 中的 token 写入 store 后**立即 `history.replaceState(null,'',location.pathname)` 清除 fragment**，再拉 `/users/me`、进首页；**不再 XHR 直调回调地址**。失败按 `error` 提示。
- 企微扫码：仅渲染 `corpId/agentId`，`corp-secret` 不下发（02 §2.7）；扫码后前端 XHR 调 `GET /api/v1/auth/wechat/callback?code=` 换取 token（独立 Controller 回调，非 OIDC 过滤器）。
- token 存储：`auth` store（内存）+ refresh 持久化；登出调 `/auth/logout`。
- 首登强制改密：`must_change_password=1` → 引导改密（`PUT /api/v1/users/{id}/password`）。

### 5.2 布局（DefaultLayout，三栏）
- **左栏 `BbFilterRail`**：固定六视图（含未读计数 `/tasks/count`）+ `BbCategoryTree` + `BbOrgTree`（人员筛选）+ 自定义栏入口 + 标签入口。
- **中栏 `BbMainContent`**：任务列表（`BbTaskList`，含 `BbTaskComposer` 内联新增 + `BbTaskCard` 列表）；空态 `BbEmpty`。
- **右栏 `BbTaskDetailDrawer`**：任务详情（编辑/子任务/参与人/标签/附件）。
- 响应式：窄屏抽屉化左栏（桌面优先，非目标移动端）。

### 5.3 任务模块（核心）
#### 5.3.1 六大视图
- 统一 `TaskView`，按 `scope` 调 `GET /api/v1/tasks?scope=`；口径以 02 §4.4 为准（day 含过期未完成等）。
- 计数：`GET /api/v1/tasks/count` 缓存于 `task` store，操作后失效刷新。
- **关键字搜索**：列表页关键字输入 → `keyword`（匹配 title/content），与 `scope` 叠加（02 §4.4）。
- **主管「含下属任务」（0305/D1，ADR-012）**：`scope=all` 且当前用户为部门负责人（`GET /departments` 中任意 `leaderId` = 本人）时，显示「含下属任务」开关 → `subordinate=true`。**下属任务为只读**：卡片/详情隐藏编辑、完成、删除、参与人等写入口（由后端 `assertVisible`/`assertWritable` 双判，前端以 `task.readonly` 标记控制展示）。

#### 5.3.2 任务卡片 `BbTaskCard`（行为见 §2.3.1 契约）
- 完成/取消：`POST /tasks/{id}/complete|uncomplete`，乐观更新 + 失败回滚。
- 收藏：`POST|DELETE /tasks/{id}/collect`。
- 移动任务：`POST /api/v1/menus/{id}/items`。
- 删除：二次确认 → `DELETE /tasks/{id}`（软删）。
- 元信息行 `BbTaskMetaLine`：日期（逾期/临期着色）、重复、提醒、标签（含紧急/重要着色）、附件图标、`@人员`。

#### 5.3.3 新增/编辑 `BbTaskComposer` / `BbTaskDetailDrawer`
- 字段：`title/content/dueAt/remindAt/priority/cycleRule/categoryId/assigneeIds[]/ccIds[]/tagIds[]/fileIds[]`（对应 `POST /tasks` 请求体，02 §4.5）。
- 子任务：`parent_id` 语义（主/子同表），`BbSubtaskList` 调 `GET /tasks/subtasks?parentId=`。
- 周期 `BbRepeatSelect` → `cycle_rule` JSONB（完整字段 `{freq,interval,dtstart,byDay,count,until,tz}`，**全新格式，非旧 `task_cycle` 字符串**；`dueAt` 即基准 `dtstart`）。周期任务为**计算式展开**，前端按后端展开的实例展示（`frequency` 段显式显示未来 N 次），不物化多行（契约为 02 §4.3）。
- 附件：上传 `POST /files` → 绑定 `fileIds`；列表来自 `attachment`（按 `task_id`）。

#### 5.3.4 分类 / 标签 / 自定义栏 / 收藏
- 分类树 `BbCategoryTree`：`GET/POST/PUT/DELETE /categories`。
- 标签 `BbTagConfig`：`/tags` CRUD。
- 自定义栏：`/menus` CRUD + `/menus/{id}/items` 增删。
- 收藏：卡片星标 + 收藏视图。

#### 5.3.5 日历
- `TaskCalendarView` + `BbCalendarCard`：`GET /api/v1/tasks/calendar?start=&end=`。

### 5.4 组织与用户模块
- `DeptManage`：部门树 CRUD（`/departments`）+ **部门负责人 `leaderId` 设置**（负责人下拉选人；02 §3.2/§3.4，支撑主管可见下属任务）。
- `UserManage`：用户列表/新建/更新/禁用/改密（`/users`，ADMIN）；普通用户仅 `GET /users?deptId=&keyword=` 供选择器。
- `BbUserSelect`：优先本部门人员；手机号对普通用户脱敏（02 §3.6）。
- 组织同步状态展示（PULL 模式）：`GET /org/sync/status`、手动 `POST /org/sync`（ADMIN）。

### 5.5 附件与预览
- 上传 `POST /api/v1/files`（multipart，`taskId` 可选），进度与大小/类型校验（白名单见 02 §5.2）。
- 下载 `GET /api/v1/files/{id}`；预览 `GET /api/v1/files/{id}/preview`（kkfileview，后端按 id 鉴权后代理）。
- 不暴露物理路径（按 id 访问）。

### 5.6 审计日志模块（ADMIN）
- `AuditLog`：操作日志 `GET /api/v1/audit/operates`、登录日志 `GET /api/v1/audit/logins`，分页 + 条件过滤。
- 复用 `BbTable` + `BbPagination`。
